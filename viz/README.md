# viz — LEDGER: AI:GO Squad Trace Viewer

AI:GO **워크스페이스 폴더**를 고르면 실행 목록이 뜨고, 그중 하나를 골라 분석하는 **단일 HTML 파일**.
백엔드 없음, 빌드 도구 없음, CDN 없음, 네트워크 의존 0.

```bash
bash viz/tools/build.sh                    # → viz/trace-visualizer.html
```

`viz/trace-visualizer.html` 을 더블클릭한 뒤 **AI:GO 워크스페이스 폴더**를 고르면 된다.
`logs/` 가 아니라 그 상위 폴더다. `.squad.json` 과 `tasks/`, `artifacts/` 가 거기 있다.

| 파일 | 역할 |
|---|---|
| `src/app.html` | 앱 원본 |
| `tools/build.sh` | 산출물 생성 + 외부 요청·잔재 마커 검사 |
| `tools/snapshot-logs.sh` | **로그 스냅샷** — 아래 "로그는 덮어써진다" 참고 |
| `trace-visualizer.html` | **산출물.** 이것만 있으면 된다 |
| `runs/` | 스냅샷 보관 디렉토리 (gitignore 대상) |

## 입력

**워크스페이스 폴더를 고르거나 끌어다 놓는다.** `logs/` 만 넣으면 `.squad.json` 과 `artifacts/` 를 놓친다.
스냅샷 폴더 여러 개를 한꺼번에 넣어도 되고, **`executionId` 로 중복을 제거해 병합**한다.

읽는 파일 (이름으로 판별):

| 파일 | 필수 | 여기에만 있는 것 |
|---|---|---|
| `history.json` | **★ 필수** | **응답 본문(`output`)**, 에이전트 이름, 요청 원문 |
| `events.jsonl` | **★ 필수** | **웨이브 구조**, `plannerWarning`, 토큰 시계열, 실패 에러 |
| `<executionId>.jsonl` | 선택 | 사람이 읽는 로그 (`level` 구분) |
| `tasks/*.json` | 선택 | `dependsOn` (태스크 의존 관계) |
| **`.squad.json`** | **★ 강력 권장** | **스쿼드 구성·모델·도구·시스템 프롬프트** (아래 참고) |
| `artifacts/*` | 선택 | 에이전트가 워크스페이스에 쓴 파일 (아래 참고) |
| `index.json` | 무시 | `history.json` 에서 전부 유도 가능 |

### 스쿼드 구성은 로그에 없다

로그에는 **태스크를 배정받은 에이전트만** 남는다. 한 번도 일하지 않은 구성원과
**플래너는 이름 자체가 안 나온다.**

실측: 로그에 등장하는 에이전트는 `Backend Developer` · `Frontend Developer` · `Code Reviewer`
3명뿐인데 실제 스쿼드는 **4명**이었다. 4번째는 플래너다 — 계획만 세우고 태스크를 받지 않으므로
`agentId` 도 `agentName` 도 로그에 없고, `plan-ready` 이벤트가 났다는 사실로만 존재를 안다.

`.squad.json` 이 없으면 전 실행에 걸친 합집합으로 로스터를 만들고, 계획 이벤트가 있으면
`(플래너)` 자리만 세운다. 추론이라 이름도 모델도 알 수 없다.

**`.squad.json` 이 답이다.** 워크스페이스 최상위에 있고 여기에 전부 들어 있다.

| 필드 | 내용 |
|---|---|
| `config.agents[].name` / `.icon` | 이름과 아이콘 |
| `config.agents[].role` | `{type:"planner"}` 또는 `{type:"custom", value:"Backend Developer"}` |
| `config.agents[].modelPreferences.preferredModelId` | **모델 이름.** 로그에는 없다 |
| `config.agents[].toolConfig.enabledTools` | 그 에이전트가 쓸 수 있는 도구 |
| `config.agents[].systemPrompt` | 시스템 프롬프트 전문 |
| `config.plannerAgentId` | 플래너가 누구인지 |

실측값: 8개 에이전트 전부 `unsloth/gpt-oss-20b`.

둘 다 없으면 안 된다 — `events.jsonl` 에는 `agentName` 이 없고(`agentId` 만), `history.json` 에는 웨이브와 `plannerWarning` 이 없다. 실측으로 확인했다.

시각은 ISO 8601. 깨진 줄은 건너뛰고 나머지를 읽는다.

## ⚠ 로그는 덮어써진다

`index.json` · `events.jsonl` · `history.json` 은 append 가 아니라 **롤링 윈도우**다.

실측: 이벤트 id `0~50` 을 담고 있던 파일이 `51~100` 으로 통째로 갈렸고, `history.json` 에는 실행 3개만 남았다.
카운터가 리셋된 게 아니라 앞쪽이 잘려 나갔다.

**실행 하나당 이벤트 9개다. 42문항을 돌리면 끝났을 때 마지막 몇 문항만 남는다.**
응답 본문은 `history.json` 에만 있고, 그게 채점 적격성 검사의 유일한 원천이다.

그래서 실행 중에는 스냅샷을 떠야 한다:

```bash
bash viz/tools/snapshot-logs.sh squad/test viz/runs --watch 5
```

`logs/` 가 바뀔 때마다 `viz/runs/<UTC타임스탬프>/` 로 통째로 복사한다.
셸은 파일 복사만 하고, **중복 제거는 뷰어가 JavaScript 로** 한다 — JSON 병합을 셸에서 하다 깨지면 원본까지 잃기 때문이다.

## 화면

### 채점 적격성 (실행을 고르기 전 첫 화면)

> **"우리 스쿼드가 성공했다고 보고한 것 중 실제로 점수가 되는 건 몇 개인가?"**

판정은 응답 텍스트 검사로만 한다. **LLM 호출 0회.**
AI:GO 는 에이전트가 응답을 반환하면 성공으로 보지만, judge 는 요구된 형식 안쪽만 읽는다.

### 출력 계약은 문항마다 다르다

요청 지문의 `=== REQUIRED OUTPUT ===` 절에서 읽는다. 실측된 두 가지:

| 계약 | 형식 | 트랙 |
|---|---|---|
| `patch` | `*** PATCH START ***` … SEARCH/REPLACE … `*** PATCH END ***` | coding |
| `boxed` | `FINAL ANSWER: \boxed{<answer>}` | math |

**계약을 안 보고 한쪽만 검사하면 다른 쪽이 통째로 오판된다.**
`\boxed{}` 안에는 `\frac{a}{b}` 같은 중첩 중괄호가 흔해서 정규식으로 못 자른다 — 짝을 세어 읽는다.

`boxed` 의 `FINAL ANSWER:` 접두사는 **권장으로만** 본다. 지문은 요구하지만
"여러 개면 마지막 것을 쓴다"는 규칙이 `\boxed{}` 를 가리키는 것으로 읽히고
math_verify 계열 채점기는 보통 마지막 `\boxed{}` 만 뽑는다. 실제로 필수인지는 확인되지 않았으므로
이것 하나로 "채점 불가"를 단정하지 않는다.

**0점을 두 종류로 나눈다** — 합치면 "무엇을 고쳐야 하는가"가 화면에서 사라지기 때문이다.

| | 뜻 | 고칠 수 있나 |
|---|---|---|
| **호출 거부** | 모델이 요청을 받지도 못했다 (컨텍스트 초과·인프라 오류) | 프롬프트·형식으로는 불가. 설정 문제 |
| **마커 없음** | 실행됐고 답도 나왔는데 패치 마커가 없어 0점 | **★ 여기가 우리 영역** |

비율은 **호출 거부를 분모에서 뺀 위에서만** 낸다.

(SWE-bench 2건은 컨텍스트 초과로 호출 거부 — 분모에서 빠진다)

주의: 실패한 태스크도 `output` 에 `"Task assigned to \`X\` failed."` 라는 자리표시 문자열이 들어간다.
출력 유무가 아니라 **태스크 상태**로 판정해야 한다.

### 장부 대조

좌: judge 가 보낸 요청 원문 (출력 계약 부분 강조) · 우: 우리가 낸 응답에 `GRADED` / `NOT GRADED` 도장.
**화면이 렌더링하는 바이트는 로그에 기록된 그 바이트다.**

`finalResult` 와 각 태스크 `output` 을 **모두** 검사해 나란히 보여준다 —
judge 에게 실제로 전달되는 것이 어느 쪽인지 아직 확인되지 않았기 때문이다.

검사 항목: START 마커 · END 마커 · `SEARCH`/`=======`/`REPLACE` 짝 · 블록마다 경로 줄.
돌려주는 것이 "다시 해봐"가 아니라 **어느 검사가 왜 실패했는지**라서, 재시도에 실제로 쓸 수 있는 신호가 된다.
이게 곧 LEDGER 주제의 Preflight 다.

### ▶ 재생

녹화된 로그만으로 실행을 시간순으로 되돌린다. **모델 호출 0회**이므로 몇 번을 돌려도 비용이 0이다.
06번 문서 §7: *"실시간은 데모 리스크가 크다. 재생 모드는 네트워크가 죽어도 살아남고 타임라인 스크러빙이 공짜로 따라온다."*

**스쿼드 맵** — 재생선이 지나가면 노드가 켜지고, 도는 중인 노드는 맥동하고,
간선에 흐름이 흐르고, 에이전트에 토큰이 붙는다.
이 실행에서 태스크를 받지 않은 구성원은 **점선 + 흐림 = 미참여**로 같이 그린다.

```
              ┌→ Frontend Developer ✗
요청 → 플래너 ⚠ ┼→ Backend Developer  ✗ → 집계 → 실행 불가 ✗
              └→ Code Reviewer      ✗
```

플래너 폴백(⚠)이 만든 3갈래 팬아웃이 그림으로 드러난다 — 문항 하나에 풀 컨텍스트 호출이 에이전트 수만큼 발생한다는 뜻이다.

**노드를 클릭하면 그 구간만 재생한다.** 시작 1.2초 전으로 이동해 재생하고 구간이 끝나면 자동 정지.
`Tab` + `Enter` 로도 된다. 미참여 노드는 "재생할 구간이 없다"고 알려주고,
요청·결과 같은 순간 노드는 그 지점으로 이동만 한다. ▶ 버튼은 언제나 전체 구간 재생이다.

컨트롤: ▶/⏸ · ↺ · 속도(1×~60×) · 스크럽 슬라이더.
계기: 경과 · 누적 토큰 · 완료 · 실패 · 현재 위상. 이벤트 티커가 재생선을 따라 한 줄씩 나타난다.

**에이전트별 토큰은 추정치다.** 로그의 `perAgentTokenUsage` 와 태스크별 `tokenUsage` 는 전부 `{0,0}` 이고,
`token-usage-update` 는 에이전트의 **평생 누적**이라 실행별 귀속에 쓸 수 없다.
그래서 누적 곡선의 증분을 그 시각에 돌던 태스크에 귀속시키고 화면에 `(추정)`을 붙인다.
동시에 여러 태스크가 돌던 구간의 증분은 나누지 않고 **미귀속**으로 남긴다 — 지어낸 숫자를 올리지 않기 위해서다.

상단 "누적 토큰"은 **보고된 시점에만 계단식으로** 오른다. 사이를 선형 보간하면
"20초 시점에 661토큰" 같은 로그에 없는 숫자가 생긴다 (실제 첫 보고는 +84초다).

### 타임라인 / 위상

플래닝 · 승인 대기 · 실행 · 집계로 나눈 막대. 성공한 실행 기준 **플래닝 49.0s / 승인 대기 20.8s / 실행 23.2s**.

`autoApprove: false` 인 실행에서는 "승인 대기"가 사람이 계획을 승인하기까지 걸린 시간이므로
시스템 성능이 아니다. 화면에 그 사실을 같이 적는다.

### 실패 분류

에러 문자열을 규칙표로 분류하고 **규칙표를 화면에 같이 보여준다** — 추측이 아니라 규칙임을 확인할 수 있도록.
열거형 이름은 제출 서버 OpenAPI 의 `FailureKind` / `FailureOwner` 를 따른다.

| 패턴 | kind | owner |
|---|---|---|
| `exceeds the available context size` | `context_overflow` | `configuration` |
| `HTTP 5xx` | `upstream_error` | `organizer` |
| `HTTP 429` / rate limit | `rate_limit` | `policy` |
| timeout / deadline | `wallclock_cap` | `policy` |
| 그 외 | `unclassified` | — |

## 로그에 없어서 못 만드는 것

| 화면 | 막힌 이유 |
|---|---|
| 캐시 히트 곡선 | **캐시 필드가 로그에 없다.** 포털 `dev-usage` 에서만 나온다 |
| 모델별 비용 | **모델 이름이 로그 어디에도 없다.** payload 키 39종 전수 확인 |
| 태스크별 토큰 | `history.json` 의 태스크별 `tokenUsage` 가 전부 `{0,0}` |
| 에이전트별 토큰 | `perAgentTokenUsage` 가 전부 `{0,0}`. `token-usage-update` 는 **에이전트 평생 누적**이라 실행별 귀속에 못 쓴다 |
| 캘리브레이션 곡선 | confidence 신호가 없다 |

실행별 총 토큰(`totalTokenUsage`)은 정확하다. 문항 = 실행이므로 문항 단위 비용 분석에는 문제가 없다.

**플래너 호출 토큰은 집계에서 빠져 있다.** 성공한 실행에서 플래너가 49초를 썼는데 토큰 이벤트가 하나도 없다.
로컬 집계와 포털 청구가 어긋날 것이다.

## 러너·설정 팀에 필요한 것

1. **컨텍스트 4096 → 32k 이상.** 지금은 coding 문항이 100% `HTTP 400` 으로 죽는다 (`request (14082 tokens) exceeds the available context size (4096 tokens)`)
2. **출력 계약 강제.** 워크스페이스에 파일을 쓰지 말고 최종 응답 텍스트에 패치 블록을 낼 것 — judge 는 워크스페이스를 보지 않는다
3. 로그에 모델 이름 남기기
4. 태스크 완료 시 에이전트별 토큰 델타 기록 (지금은 일부 에이전트가 업데이트를 아예 못 받는다)

## artifacts/ — 답을 파일에만 쓴 경우

에이전트에게 `write_file` 도구가 열려 있으면 결과를 워크스페이스 파일로 쓴다.
**judge 는 워크스페이스를 읽지 않는다. 응답 텍스트만 읽는다.**

실측: `squad/test_2/artifacts/final_answer.txt` 에

```
Final amount: **≈ $32,328**
```

가 들어 있는데 응답 텍스트에는 `FINAL ANSWER: \boxed{}` 가 없다. 답은 나왔지만 0점이다.
같은 일이 `solution.py`, `distance_squared.py`, `final_amount.txt` 에서도 일어났다.

뷰어는 `artifacts/` 를 읽어 파일 목록을 보여주고, 이름에 `final` / `answer` / `solution` / `result`
가 들어간 파일이 있는데 응답이 채점 불가면 **경고를 띄운다.**
`artifacts/reports/` 는 AI:GO 가 만든 실행 요약이라 제외한다. 에이전트가 쓴 것이 아니다.

원인은 프롬프트에 있다. `.squad.json` 의 `systemPrompt` 는 "구현하세요", "작성하세요"라고만
말하고 출력 계약을 한 번도 언급하지 않는다. 도구가 열려 있고 프롬프트가 파일 작업을 시키면
파일을 쓰는 쪽이 자연스러운 행동이다.


## tasks/*.md — 시도 단위 기록

```
- [08:31] Started execution (attempt 1)
- [08:32] Failed (terminal)
```

시도 번호는 `events.jsonl` 에 없고 이 파일에만 있다. 태스크 표에 그대로 보여주고
시도가 2회 이상이면 배지를 단다.

전수 조사에서 확인한, 값이 비어 있어 화면에 올리지 않은 것들.

| 필드 | 실측 |
|---|---|
| `tasks/*.json` 의 `result` | 25건 전부 `null` |

## 세 가지 모드

상단 줄에서 바꾼다. `m` 키로도 순환한다.

| 모드 | 무엇을 보나 |
|---|---|
| **실행 하나** | 좌측 목록에서 실행을 골라 개요·재생·장부 대조·타임라인·실패 분류·원문 로그 |
| **전체 분석** | 모든 실행을 한꺼번에. 간트 · 낭비 사분면 · 토큰 곡선 · 답 근접도 · 응답 길이 |
| **스쿼드 비교** | 워크스페이스끼리 비교. 워크스페이스 하나가 스쿼드 하나다 |

### 전체 분석

- **간트** — 모든 실행을 한 시간축에. 색은 위상(플래닝·승인 대기·실행·집계).
  실행 사이의 빈칸이 아무도 일하지 않은 시간이다.
- **낭비 사분면** — x = 문항당 과금 토큰(log), y = 채점 적격 여부.
  오른쪽 아래가 낭비의 총량이다. 슬라이더를 끌면 *"여기서 끊었다면 토큰 −X / 적격 −Y건"*
  이 즉시 다시 계산된다. **모델 호출 0회.**
  잘린 실행의 적격은 전부 잃는 것으로 계산하므로 이 곡선은 손실의 상한이다.
- **토큰 누적 곡선** — 실행별 곡선을 겹쳐 그린다. 계단이 가파른 구간이 비용이 몰린 곳이다.
- **답 근접도** — 형식을 못 맞춘 실행이 얼마나 아까웠는지. 통과한 검사 수로 나눈다.
  통과율이 높은 것부터 손대면 빠르다.
- **응답 길이 대 적격** — 길게 쓴다고 맞는 것이 아님을 본다.

### 스쿼드 비교

워크스페이스 하나가 스쿼드 하나다. 로스터도 워크스페이스별로 따로 만든다 —
섞으면 `test` 의 Backend Developer 와 `ikkim` 의 백엔드 개발자가 한 줄로 합쳐져 비교가 불가능해진다.

채점 적격률·문항당 토큰·문항당 시간·실제 실행 시간을 나란히 놓고 가장 나은 값에 색을 준다.
**같은 요청을 여러 스쿼드가 푼 경우**를 찾아 따로 묶는다. 조건이 같으니 차이가 곧 스쿼드 차이다.

문항당 시간에는 승인 대기가 들어 있어 시스템 성능이 아니다. 그래서 실제 실행 시간을 따로 뒀다.

## 탐색

| 조작 | 하는 일 |
|---|---|
| `j` / `k` (또는 ↑↓) | 실행 이동 |
| `1`~`6` | 탭 전환 |
| `m` | 모드 순환 |
| `/` | 검색으로 이동 |
| `?` | 단축키 도움말 |
| `b` | 왼쪽 목록 접기 / 펴기 |
| `Esc` | 입력에서 빠져나오기 |

- **검색** — 요청 원문·스쿼드·에이전트 이름·태스크 제목·에러 문자열을 한꺼번에 훑는다.
- **스쿼드 필터** — 워크스페이스가 둘 이상일 때만 나온다.
- **목록 / 카드 전환** — 문항이 많아지면 카드 격자가 낫다.
- **미니 막대** — 각 행에 토큰·시간을 전체 대비 비율로 깐다. 훑어보는 속도가 달라진다.
- **URL 상태** — 모드·선택·탭·검색·필터가 주소 해시에 담긴다.
  새로고침해도 남고, **특정 화면을 링크로 건넬 수 있다.**
  sandbox 나 `data:` origin 에서는 `replaceState` 가 던지므로 감싸 두었다. 주소 갱신이 앱을 죽이면 안 된다.


## 화면 배치

- **오프닝** — 폴더를 고르기 전에는 스쿼드 맵이 흐르는 배경과 이 뷰어가 무엇을 보는지 네 장의 카드가 보인다.
  여기서도 언어를 고를 수 있다. 처음 여는 사람이 한국어를 못 읽어 막히는 일이 없어야 한다.
- **왼쪽 목록** — 손잡이를 끌어 180~720px 사이로 넓힌다. 두 번 누르면 기본값. `b` 로 접는다.
  접힌 상태는 "실행 하나" 모드에서만 의미가 있으므로 다른 모드에서는 손잡이째 감춘다.
- **전체 분석 / 스쿼드 비교** — 이 두 모드는 실행 하나를 보는 화면이 아니다.
  그래서 목록과 상세 패널(`.body`)을 통째로 감춘다. 화면에 남는 것은 그 모드가 답하는 질문뿐이다.
- **기본값 없음** — 아무것도 고르지 않았을 때 개요를 미리 띄우지 않는다.
  고르지 않은 상태와 고른 상태가 같아 보이면 무엇을 보고 있는지 알 수 없다.

## 한국어 / 영어

오른쪽 위 콤보로 바꾼다. 오프닝 화면에도 같은 콤보가 있다.

번역은 사전 하나로 끝낸다. **키가 한국어 원문**이라서 화면에 새 문장을 넣어도 사전에 없으면 그대로 나올 뿐 깨지지 않는다.

찾는 순서는 네 단계다. 앞에서 걸리면 뒤는 보지 않는다.

1. **문단 통째** — `.q` `.note` `.tip` 같은 설명 문단은 요소 단위로 바꾼다.
   문단 안에 `<b>` 와 값이 섞여 텍스트 노드가 조각나므로, 조각을 사전에 담아봐야 뜻이 서지 않는다.
2. **텍스트 노드 그대로** — 공백을 접어 키로 삼는다. 템플릿 문자열의 들여쓰기가 그대로 들어오기 때문이다.
3. **자리표시자** — `태스크 3개` 처럼 숫자만 다른 라벨은 `태스크 {0}개` 로 찾아 숫자를 도로 끼운다.
4. **규칙** — `누적 12.5k (in 10.2k · out 2.2k)` 처럼 숫자와 단위가 자유롭게 섞이면 정규식으로 바꾼다.
   자리표시자로 잡으려면 조합마다 키가 하나씩 필요해진다.

그래도 남는 조각은 부분 일치로 이어 붙인다. 긴 키부터 시도해야 짧은 조각이 먼저 걸려 문장을 반쪽만 바꾸는 일이 없다.

**데이터는 건드리지 않는다.** 요청 원문·응답·에러 문자열·에이전트 이름은 로그의 내용이지 UI 가 아니다.
`.scroll` 과 `[data-raw]` 안쪽은 순회에서 아예 제외한다.

되돌리려면 원문이 있어야 하므로 바꾸기 전에 `WeakMap` 에 담아 둔다. 패널은 다시 그려지지만 오프닝 화면은 정적이라 특히 그렇다.

`i18nAudit()` 을 콘솔에서 부르면 지금 화면에 남은 한국어를 돌려준다.
실제 로그 109개 파일·13개 실행을 모든 모드와 탭에서 훑어 UI 문구가 0개 남을 때까지 맞췄다.
남는 한국어는 스쿼드 이름과 에이전트 이름뿐이고, 그것은 로그의 값이라 바꾸면 안 된다.
