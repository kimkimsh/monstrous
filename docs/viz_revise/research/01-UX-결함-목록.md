# 01. UX 결함 목록 — 인상이 아니라 측정값

"UX/UI가 개판"이라는 판단을 **재현 가능한 숫자**로 바꾼 문서다. 각 항목에는 파일과 줄 번호, 그리고 그 결함이 사용자에게 무엇을 하는지가 붙는다.

측정 대상: `viz/src/app.html` (2026-08-23 기준)

**측정 방법 두 가지를 구분한다.** 정적 개수는 `grep`, 화면 위 크기는 **1440×900 뷰포트에서
`getBoundingClientRect()`** 로 잰 값이다. 둘을 섞으면 C-1 처럼 틀린다 — 처음에는 CSS 의
`padding` 과 `font-size` 만 더해서 조작부를 119px 로 적었는데, `line-height` 와 테두리를
빼먹은 값이었다. 실측은 **158px** 이다.

---

## A. 시각 체계가 없다

### A-1. 글자 크기가 14종이고, 그중 79%가 11.5px 이하다 — `HIGH`

CSS `font-size` 선언 67개의 분포:

| 크기 | 선언 수 |
|---|---|
| 9px | 1 |
| 9.5px | 7 |
| 10px | 18 |
| 10.5px | 9 |
| 11px | 12 |
| 11.5px | 6 |
| 12px | 3 |
| 12.5px | 1 |
| 14px | 2 |
| 15px | 2 |
| 18px | 1 |
| 19px | 4 |
| 20px | 1 |

여기에 SVG 속성형 `"font-size": 8.5 / 9 / 9.5` 가 **선언 14개** 더 있다. 그중 `9` 와 `9.5` 는
위 표에 이미 있으므로 새로 늘어나는 것은 `8.5` 하나뿐이다. **합집합 14종** (선언은 67 + 14 = 81개).

`9px`, `9.5px`, `10px`, `10.5px` 가 서로 다른 크기로 존재하는 것은 스케일이 아니라 그때그때 고른 값이다. 0.5px 차이는 사람이 구분하지 못하면서 **일관성만 잃는다.**

> **사용자에게 무엇을 하나:** 위계가 안 읽힌다. 화면의 90%가 "작은 글씨" 한 덩어리라, 무엇이 결론이고 무엇이 각주인지 크기로 구분되지 않는다. 심사위원은 결론을 찾아 읽어야 한다.

### A-2. 모서리 반지름이 8종이다 — `MEDIUM`

`border-radius`: `2px` ×4, `4px` ×3, `5px` ×3, `6px` ×4, `7px` ×1, `8px` ×1, `9px` ×4, `10px` ×2. SVG `rx` 는 `2` ×3, `5` ×1.

중첩 규칙(바깥 반지름 = 안쪽 반지름 + 패딩)도 없다. `.card`(9px, padding 14px) 안의 `pre`(6px)는 규칙대로면 `9 - 14 < 0`, 즉 각져야 한다.

### A-3. 인라인 스타일이 89개다 — `MEDIUM`

렌더 함수가 색과 굵기를 마크업 문자열 안에서 정한다.

```js
// app.html:1917
$("#s-grad").style.color = ran.length && gradRan < ran.length ? "var(--bad)" : "var(--ok)";
```

색 규약을 바꾸려면 CSS가 아니라 **JavaScript 89군데**를 고쳐야 한다.
(`grep -o 'style="' | wc -l` = 89 선언 / `grep -c` = 85 줄. 한 줄에 둘이 있는 곳이 있어서
줄로 세면 적게 나온다 — 검사 스크립트도 이 함정에 빠져 있었다. `../spec/04` §5.) 이번 개편이 CSS만 갈아엎어서는 끝나지 않는 이유다.

## B. 읽을 수 없다

### B-1. 가장 흐린 글자색이 WCAG AA에 못 미친다 — `HIGH`

`--fg-faint: #5b6675` on `--bg: #0e1116`

| 항목 | 값 |
|---|---|
| 상대 휘도 (fg-faint) | 0.1301 |
| 상대 휘도 (bg) | 0.0055 |
| **명암비** | **3.25 : 1** |
| WCAG AA 본문 기준 | 4.5 : 1 |
| WCAG AA 큰 글자(18.66px+) 기준 | 3.0 : 1 |

`--fg-faint` 는 `9px`~`10.5px` 크기로 **35개 선언**에서 쓰인다. 큰 글자 예외에 해당하지 않는다.

`--fg-dim: #8b98a8` 는 6.44:1 로 통과한다. 문제는 가장 흐린 층 하나다.

> **사용자에게 무엇을 하나:** 눈금 라벨, 태스크 시도 기록, 툴팁 보조 문구, 범례가 전부 이 색이다. **프로젝터에서 중간 톤이 죽으면 통째로 사라진다.** 고대비 모드(`◐`)가 이미 있다는 사실이 이 문제를 팀이 이미 겪었다는 증거다.

### B-2. 본문 전체가 고정폭 글꼴이다 — `MEDIUM`

```css
/* app.html:24 */
body{ ... font:13px/1.55 var(--mono); ...}
```

`--mono` 는 `ui-monospace, "Cascadia Mono", "JetBrains Mono", Consolas, "DejaVu Sans Mono", monospace`.

**한국어에 고정폭 글꼴 스택은 위험하다.** 나열된 다섯 폰트 중 한글 글리프를 가진 것이 없어, 한글은 전부 시스템 폴백으로 렌더된다. 라틴은 고정폭, 한글은 비례폭이 되어 **한 줄 안에서 리듬이 깨진다.** 화면 문구가 대부분 한국어인 도구에서 이건 우연한 결과지 선택이 아니다.

고정폭이 정말 필요한 곳은 세 군데뿐이다 — 숫자 열, 요청·응답 원문, 코드/마커.

### B-3. 정보 밀도가 균일하다 — `HIGH`

`.card` 하나가 모든 것을 담는다. 제목 14px, 설명 11px, 표 11.5px. **채점 적격성이라는 결론과 `logs/index.json` 대조라는 각주가 같은 상자, 같은 크기로 나온다.**

`paneOverview` 는 카드 6개를 세로로 쌓는다(2045-2143): 실행 개요 → AI:GO 요약 대조 → 워크스페이스 파일 → 스쿼드 구성 → 시간 → 태스크 표. 스크롤 없이 보이는 것은 첫 카드뿐이고, 그 첫 카드 안에서도 결론(`채점 적격`)은 `<dl>` 일곱 번째 행이다.

## C. 화면이 낭비된다

### C-1. 조작부가 3층으로 158px를 쓴다 — `HIGH`

1440×900 에서 `getBoundingClientRect()` 로 잰 값이다.

| 요소 | 실측 | 내용 |
|---|---|---|
| `header` | **62.1px** | 브랜드 · 통계 5개 · 버튼 7개 |
| `.modes` | **47.1px** | 접기 · 모드 3개 · 검색 |
| `.tabs` | **49.1px** | 탭 6개 + 힌트 |
| **합계** | **158.3px** | `.pane` 의 `top` 이 실제로 158 |

`header` 가 62px 인 이유는 `.stat` 이 3줄이기 때문이다 — `span` 9.5px + `b` 15px + `em` 10px 에
`line-height:1.25` 가 붙어 43.1px, 거기에 패딩 18 + 테두리 1.

> **처음에는 이 값을 119px로 적었다.** `padding` 과 `font-size` 만 더하고 `line-height` 와
> 테두리를 뺀 계산값이었다. 실측이 39px 더 크다. **결함은 생각보다 나쁘고, 그래서 등급도
> `MEDIUM` 이 아니라 `HIGH` 다.**

1080p 세로에서 **본문이 시작되기 전에 14.7%를 쓴다.** 세 줄 모두 항상 떠 있고, 모드가
`all`/`cmp` 일 때는 탭 줄이 숨지만 그 자리는 비워진다.

### C-2. 차트가 작고 라벨이 9px다 — `HIGH`

| 차트 | 뷰박스 | 실제 높이 | 라벨 크기 |
|---|---|---|---|
| 간트 (`drawGantt` 2298) | 1000 × (행수×17+34) | 최대 460px | 9px |
| 낭비 사분면 (`drawWaste` 2323) | 520 × 250 | 250px | 9px |
| 토큰 곡선 (`drawTokenCurves` 2361) | 520 × 230 | 230px | 9px |
| 응답 길이 (`drawLen` 2412) | 520 × 230 | 230px | 9px |

`.grid2` 가 `minmax(400px, 1fr)` 로 2열을 만들어서(66행), 1440px 창에서 차트 하나가 약 640px를 받는다. 뷰박스가 520이므로 **1.23배로 확대**되어 9px 라벨이 약 11px로 보인다. 즉 라벨 크기가 창 폭에 따라 달라진다. 스케일이 두 겹으로 어긋나 있다.

**낭비 사분면은 이 도구에서 가장 중요한 화면인데** (심사위원이 직접 슬라이더를 끄는 자리, `06-시각화-설계-가이드.md` §6-1) 250px 높이의 곁다리 카드로 들어가 있다.

### C-3. 아무것도 안 고르면 안내문 한 장뿐 — `MEDIUM`

```js
// app.html:1980-1986
if(!e){ P.innerHTML = `<div class="card"><h2>실행을 고르세요</h2> …` }
```

"기본값 없음"은 옳은 원칙이지만(고른 것과 안 고른 것이 같아 보이면 안 된다), **처음 연 사람이 보는 첫 화면이 빈 카드 한 장**이라는 결과는 원칙과 무관한 손실이다. 실행 목록은 왼쪽에 접혀 있을 수도 있다.

## D. 동작이 목적을 배신한다

### D-1. 고빈도 조작에 진입 애니메이션이 걸려 있다 — `HIGH`

```css
/* app.html:311 */
.card{ animation: rp-in .22s ease-out }
```

`rp-in` 은 `translateY(-5px)` + 페이드. `renderPane()` 은 **탭 전환·실행 선택·언어 변경·검색 입력마다** 패널을 통째로 다시 그리므로, `j`/`k` 로 실행을 훑을 때 **매번 카드 전체가 위에서 떨어진다.**

`j`/`k` 는 목록을 빠르게 훑으라고 만든 키다. 훑을 때마다 220ms 애니메이션이 재시작하면 **키보드가 느리게 느껴진다.** 키보드로 시작된 동작에는 애니메이션을 걸지 않는 것이 원칙이다.

### D-2. `?` 도움말이 `alert()` 다 — `MEDIUM`

```js
// app.html:3693
if(ev.key==="?"){ alert("j/k 실행 이동 · 1~6 탭 · m 모드 전환 · / 검색 · Esc 해제"); }
```

브라우저 기본 모달이라 테마·번역·발표 모드가 전부 안 걸린다. 단축키가 9개인데 5개만 적혀 있다 (`b`, `?`, ↑↓ 누락).

### D-3. 프레스 피드백이 없다 — `LOW`

버튼에 `:active` 상태가 없다. `button:hover` 는 테두리 색만 바꾼다(28행). 누른 순간 화면이 반응하지 않는다.

### D-4. 애니메이션이 9개인데 규약이 없다 — `MEDIUM`

| 이름 | 지속 | 이징 | 용도 |
|---|---|---|---|
| `sm-travel` | 1.5s | linear | 간선 펄스 |
| `sm-blink` | 1.15s | ease-in-out | 실행 중 점 |
| `sm-ring` | 1.6s | ease-out | 포커스 링 |
| `rp-pulse` | 1.1s | ease-in-out | 실행 중 막대 |
| `rp-in` | 0.28s / 0.22s | ease-out | 티커 행 / 카드 |
| `stamp-in` | 0.34s | cubic-bezier(.2,.9,.3,1.3) | 도장 |
| `dg-run` | 3.4s | linear | 오프닝 배경 |
| `drop-in` | 0.5s | cubic-bezier(.2,.8,.3,1) | 오프닝 진입 |
| `mark-pulse` | 2.4s | ease-out | 워드마크 점 |

지속 시간이 0.22 / 0.28 / 0.34 / 0.5 / 1.1 / 1.15 / 1.5 / 1.6 / 2.4 — **아홉 개가 전부 다르다.** 이징도 5종. 시그니처 이징이 없어서 개별 동작은 괜찮은데 **전체가 한 물건처럼 안 느껴진다.**

`transition:` 은 10개뿐이라 상태 변화 대부분이 즉시 튄다. `transition: all` 은 다행히 없다.

## E. 잘하고 있는 것 (버리면 안 되는 것)

개편이 퇴행이 되지 않도록, 지금 이미 옳은 것을 같이 적는다.

| 잘한 것 | 근거 |
|---|---|
| **각 카드가 답하는 질문을 한 줄로 적어 둔다** (`.q`) | `06-시각화-설계-가이드.md` §9의 함정 "예쁜데 질문에 답 못 함"을 정면으로 피한 설계 |
| **판정 근거 규칙표를 화면에 같이 보여준다** (`paneFailure` 3330) | 추측이 아니라 규칙임을 확인시킨다 |
| **모르는 것을 불합격으로 적지 않는다** (`gradable: null`) | `판정 보류` / `계약 미전송` 을 `답 형식 없음` 과 분리 |
| **추정값에 `(추정)` 을 붙인다** (`frame()` 2934) | 미귀속 토큰을 나누지 않고 남긴다 |
| **재생 모드가 있다** | 시연 중 네트워크가 죽어도 산다. 타임라인 스크러빙이 따라온다 |
| **URL 해시 상태** | 특정 화면을 링크로 건넬 수 있다 |
| **한국어/영어 전환** | 사전 키가 한국어 원문이라 미번역이 화면을 안 깬다 |
| **고대비·발표·인쇄 모드** | 프로젝터 시연을 이미 고려했다 |
| **SVG·JSON 내보내기** | 라이브러리 0개. CSS 변수를 실제 색으로 굳혀 내보낸다 |
