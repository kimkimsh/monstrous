# viz_revise / research — 조사 자료

시각화 프로그램(`viz/`)을 UX·UI 관점에서 전면 재작성하기 전에, **무엇이 이미 옳고 무엇이 잘못됐는지**를 먼저 확정한 조사 기록이다.

기획(`../plan/`)과 스펙(`../spec/`)의 모든 주장은 이 폴더의 관찰을 근거로 삼는다. 여기 없는 근거로 저기서 결정을 내린 곳이 있으면 그건 결함이다.

## 읽는 순서

| 문서 | 무엇이 들어 있나 |
|---|---|
| **`00-현행-viz-해부.md`** | `viz/src/app.html` 3,761줄을 계층별로 해부한 지도. **어느 줄이 로직이고 어느 줄이 UI인지**를 줄 번호로 확정한다. 재작성의 보존 경계선이 여기서 나온다 |
| **`01-UX-결함-목록.md`** | 지금 화면이 무엇을 잘못하고 있는지. 인상이 아니라 **측정값**으로 적었다 (글자 크기 16종, 명암비 3.25:1, 인라인 스타일 88개 등) |
| **`02-데이터-원천과-한계.md`** | 로그에 무엇이 있고 무엇이 없는가. **없는 데이터로 화면을 만들 수 없다** — 새 디자인이 넘을 수 없는 벽 |
| **`03-채점-6축-매핑.md`** | 시각화 30점의 여섯 축이 실제로 어느 화면 요소로 환산되는지. 이번 개편이 **어느 축을 얼마나 더 가져오려는지** |
| **`04-아트-레퍼런스-조사.md`** | "따스한 도트 아케이드"라는 요구를 실제 값으로 바꾸기 위한 조사. 폰트·색·모션의 제약과 선택지, 그리고 **버린 선택지** |

## 이 조사가 확정한 것 다섯 줄

1. **로직과 UI는 이미 물리적으로 분리돼 있다.** 파싱·판정·집계는 `app.html:539~1278`, 렌더는 `1890~3367`. 전자를 한 글자도 안 건드리고 후자만 갈아엎을 수 있다.
2. **지금 화면의 문제는 취향이 아니라 규칙 없음이다.** 글자 크기 16종, 모서리 반지름 8종, 인라인 스타일 88개. 타입 스케일도 스페이싱 스케일도 존재하지 않는다.
3. **가장 흐린 글자색이 WCAG AA에 못 미친다.** `--fg-faint`(#5b6675)는 배경 대비 **3.25:1**인데 9.5~10.5px 크기로 35군데에 쓰인다. 프로젝터에서는 사라진다.
4. **데이터 한계는 실측으로 확정돼 있다.** 캐시 히트율·모델별 비용·태스크별 토큰은 로그에 없다. **새 디자인이 이걸 그리려 하면 숫자를 지어내는 것이다.**
5. **이 뷰어의 승부처는 insightfulness 한 축이다.** 나머지 다섯 축은 이미 채워져 있다. 개편의 목표는 "예쁘게"가 아니라 **판단이 화면에서 먼저 읽히게** 하는 것이다.
