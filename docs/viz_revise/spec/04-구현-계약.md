표기 헬퍼다 (1884–1888). **같이 보존한다** — 순수 함수이고 내보내기 JSON 이 `fmt` 를 거치지 않으므로
회귀 위험은 없지만, 화면 숫자 표기가 통째로 여기서 나온다. 새로 만드는 `dur(ms)` 는

이것들은 UI 문구처럼 보이지만 **사실상 열거형이거나 판정 로직의 일부**다. 번역은 `EN` 사전이 담당한다.

## 2. 코드 규약

### 2-1. 계산과 표현의 분리

렌더 함수는 **계산하지 않는다.** 값은 P0에서 추출한 순수 함수가 준다.

```js
// ❌ 현행 — 임계값이 마크업 안에
`<td class="n"${wait&&wait>10000?' style="color:var(--warn)"':""}>`

// ✅ 새
const WAIT_WARN_MS=10000;
const cls = wait>WAIT_WARN_MS ? "n warn" : "n";
`<td class="${cls}">`
```

**인라인 `style="…"` 은 20개 이하.** 남는 것은 CSS 변수 전달 전용이다 (`--c`, `--w`, `--on`, `--cells`).

### 2-2. 색 리터럴 금지

```bash
# 검사 — CSS 변수 정의 블록 밖에 hex 가 있으면 안 된다
grep -n '#[0-9a-fA-F]\{6\}' src/app.html | grep -v '^\s*[0-9]*:\s*--'
```

예외: `--ink` 를 SVG 내보내기에서 실제 색으로 굳히는 코드 (3730-3736).

### 2-3. 컴포넌트 함수

각 컴포넌트는 문자열을 돌려주는 함수 하나다.

```js
const stamp=v=>`<span class="stamp" data-v="${v.k||"hold"}"><b>${t(v.label)}</b><em>${STAMP_EN[v.label]||""}</em></span>`;
const gauge=(on,cells,c,dim=0)=>`<div class="gauge${dim?" has-dim":""}" role="img" aria-label="…"
  style="--cells:${cells};--on:${on};--dim:${dim};--c:${c}"></div>`;
const trk =k=>`<span class="trk" data-t="${k}">${GLYPH[k]}${TRACK[k].label}</span>`;
const ava =a=>…;
```

**같은 컴포넌트가 여러 화면에서 재사용된다.** 도장이 목록·개요·장부·비교에서 같은 함수다.

### 2-4. 클래스 이름

| 접두 | 무엇 |
|---|---|
| `hud-` | 상단 바 |
| `row-` | 목록 행 |
| `sm-` | 스쿼드 맵 (현행 유지) |
| `rp-` | 재생 (현행 유지) |
| `chk-` | 검사 항목 |
| `stat-` | 계기 |
| 접두 없음 | `panel` `q` `fn` `gauge` `stamp` `trk` `ava` `stack` — 전역 컴포넌트 |

**CSS 선택자 특이도를 낮게 유지한다.** `.panel .stat-v` 정도가 상한. `.section` 과 `.cta` 처럼 서로 상쇄하는 규칙을 만들지 않는다.

## 3. i18n

### 3-1. 엔진은 그대로

`t` · `tn` · `paraKey` · `translateParas` · `translateDOM` · `rebuildLong` · `i18nAudit` (1705-1882). 4단계 탐색(문단 → 텍스트 노드 → 자리표시자 → 정규식)이 그대로다.

### 3-2. 사전 키는 전면 교체

새 화면 문구에 맞춰 `EN` 을 다시 쓴다. 규칙은 현행 그대로:

- **키가 한국어 원문.** 사전에 없으면 원문이 그대로 나온다
- **데이터는 번역하지 않는다.** `.scroll` 과 `[data-raw]` 안쪽은 순회에서 제외
- `PHASE_EN` 은 별도 사전 — `"실행"` 이 카운트의 `실행` 과 글자가 같지만 뜻이 다르다

### 3-3. 새로 필요한 것

| 항목 | 처리 |
|---|---|
| 도장 영문 라벨 | `STAMP_EN` 신설. 사전이 아니라 **상시 병기**되는 값이라 `LANG` 과 무관 |
| HUD 라벨 (`CREDITS` 등) | 영문 고정. 번역 안 함 |
| `1칸 = 100k tok` | 자리표시자 키 `"1칸 = {0} tok"` |
| 스택 막대 하단 라벨 | 일반 키 |

### 3-4. 검사

```js
i18nAudit()   // 영어 모드에서 0이 나올 때까지
```

세 워크스페이스 × 3모드 × 6탭 × 각주 펼침 상태 전부.

## 5. 빌드 검사 — `viz/tools/build.sh` 에 추가

현행 검사 두 개(외부 요청 0 · 잔재 마커 0)를 유지하고 아래를 더한다.

```bash
fail(){ echo "FAIL: $1" >&2; exit 1; }

# ── 토큰 규율 ──
# 글자 크기는 '토큰이 7종인가' 로 센다. 사용처는 전부 var(--fs-*) 라서
# 'font-size:...px' 로 세면 언제나 0 이 나오는 — 절대 실패하지 않는 — 검사가 된다.
n=$(grep -oE '^[[:space:]]*--fs-[a-z]+:[0-9.]+px' src/app.html | sort -u | wc -l | tr -d ' ')
[ "$n" -eq 7 ] || fail "글자 크기 토큰 $n 종 (정확히 7)"

# 사용처에 리터럴이 없는지 따로 본다. SVG 속성형("font-size":9)까지 잡는다 —
# 현행 파일에 그 형태가 14개 있고, 예전 검사는 그걸 통째로 놓쳤다.
grep -oE '(font-size:|"font-size":)[[:space:]]*[0-9.]+' src/app.html | grep . \
  && fail "font-size 리터럴 (var(--fs-*) 만 허용)"

# '(padding|margin|gap):' 는 '--cell-gap:2px' 안의 'gap:' 에도 걸린다 —
# 앞 경계를 넣지 않으면 검사가 자기 토큰을 위반으로 신고한다.
grep -oE '(^|[;{[:space:]])(padding|margin|gap|row-gap|column-gap):[^;}]*' src/app.html \
  | grep -oE '[0-9]+px' | sort -u \
  | grep -vE '^(0|1|2|4|8|12|16|24|32|48|64)px$' | grep . \
  && fail "4px 격자를 벗어난 간격"

grep -o 'border-radius:[^;]*' src/app.html | sort -u \
  | grep -vE 'border-radius:(0|50%)$' | grep . \
  && fail "border-radius 는 0 또는 50% 만"

# grep -c 는 '줄 수' 다. 한 줄에 두 개 있으면 하나로 샌다 (현행: 선언 89 / 줄 85).
n=$(grep -o 'style="' src/app.html | wc -l | tr -d ' ')
[ "$n" -le 20 ] || fail "인라인 style $n 개 (최대 20)"

grep -q 'transition:all' src/app.html && fail "transition: all 금지"

# 이징은 cubic-bezier 4종(--ease · --ease-pop · --ease-move · --ease-exit)뿐.
n=$(grep -o 'cubic-bezier([^)]*)' src/app.html | sort -u | wc -l | tr -d ' ')
[ "$n" -le 4 ] || fail "이징 $n 종 (최대 4)"
# 키워드 이징이 섞이면 위 검사가 못 잡는다.
grep -qE '(transition|animation)[^;}]*[[:space:]](ease|ease-in|ease-out|ease-in-out)[[:space:];}]' src/app.html \
  && fail "이징 키워드 금지 — var(--ease*) 를 쓴다"

# ── 셀 게이지 ──
# background-image 는 애니메이션 되지 않는 속성이라 이 조합은 조용히 아무것도 안 한다.
grep -qE 'transition:[^;}]*background[^;}]*steps' src/app.html \
  && fail "게이지는 --on 을 전이한다 (background 는 discrete)"
grep -q "@property --on" src/app.html || fail "@property --on 등록이 없다"

# ── 보존 경계 ──
# 줄 번호는 리팩터링 한 번에 무너진다. 마커로 감싸고 마커로 검사한다 (§7).
for k in contract failure collect model i18n load export; do
  awk "/@preserve:begin $k/,/@preserve:end $k/" .baseline/app.html > /tmp/base.$k
  awk "/@preserve:begin $k/,/@preserve:end $k/" src/app.html     > /tmp/new.$k
  [ -s /tmp/base.$k ] || fail "보존 마커 $k 가 기준선에 없다"
  diff -q /tmp/base.$k /tmp/new.$k >/dev/null || fail "보존 구간 $k 가 변경됨"
done

# ── 명암비 ──
python3 tools/contrast.py src/app.html || fail "명암비 미달"
```

> **마커가 정본이다.** 첫 초안은 줄 번호로 검사했는데, P0 에서 순수 함수를 하나만 끌어내도
> 아래 구간의 좌표가 전부 밀린다. **P0 의 첫 작업이 일곱 구간에 `@preserve` 마커를 다는 것**이고,
> 그 상태의 파일을 `.baseline/app.html` 로 고정한다. §1-1 표의 줄 번호는 그 뒤로는
> **사람이 읽는 참고값**이지 검사 기준이 아니다.
> ```js
> /* @preserve:begin contract */ … /* @preserve:end contract */
> ```
> 마커 이름 일곱: `contract` · `failure` · `collect` · `model` · `i18n` · `load` · `export`.

### 5-1. `tools/contrast.py`

```python
#!/usr/bin/env python3
"""CSS 변수 블록에서 색을 뽑아 텍스트 토큰 x 배경 토큰 명암비를 검사한다.

첫 초안에는 조용한 구멍이 둘 있었다.
  1) 색 정규식이 6자리 hex 만 받아서 `--bg:#000` 을 못 읽었다. 그러면 고대비 블록에
     `--bg` 가 없는 것으로 보이고 `continue` 로 건너뛴다 — 7:1 하한이 한 번도
     검사되지 않는다. 3자리를 받아 6자리로 펴서 해결했다.
  2) 블록이 PAIRS 에 필요한 토큰을 빠뜨려도 그냥 지나갔다. 이제는 그것 자체를
     실패로 본다. 고대비 블록이 `--ink` 를 선언하지 않던 상태가 여기 걸린다.
"""
import re, sys

PAIRS = [("--fg","--bg"),("--fg","--panel"),("--fg","--panel-2"),
         ("--fg-dim","--bg"),("--fg-dim","--panel"),("--fg-dim","--panel-2"),
         ("--fg-faint","--bg"),("--fg-faint","--panel"),("--fg-faint","--panel-2"),
         ("--ember","--bg"),("--gold","--bg"),("--lime","--bg"),
         ("--coral","--bg"),("--magenta","--bg"),("--plum","--bg"),
         ("--ember","--panel-2"),("--gold","--panel-2"),("--lime","--panel-2"),
         ("--coral","--panel-2"),("--magenta","--panel-2"),("--plum","--panel-2"),
         ("--ink","--ember"),("--ink","--gold"),("--ink","--lime"),
         ("--ink","--coral"),("--ink","--magenta"),("--ink","--plum"),
         ("--ink","--fg-faint")]          # 판정 보류 도장 = --v-hold 배경 위의 잉크
MIN = 4.5
HEX = re.compile(r"(--[\w-]+)\s*:\s*#([0-9a-fA-F]{3}|[0-9a-fA-F]{6})\b")

def norm(h):
    return "".join(c*2 for c in h) if len(h) == 3 else h

def lin(c):
    c /= 255
    return c/12.92 if c <= 0.03928 else ((c+0.055)/1.055)**2.4

def lum(h):
    h = norm(h)
    r, g, b = (int(h[i:i+2], 16) for i in (0, 2, 4))
    return 0.2126*lin(r) + 0.7152*lin(g) + 0.0722*lin(b)

def ratio(a, b):
    la, lb = lum(a), lum(b)
    hi, lo = max(la, lb), min(la, lb)
    return (hi+0.05) / (lo+0.05)

src = open(sys.argv[1], encoding="utf-8").read()
bad = 0
seen = 0
for m in re.finditer(r"(:root|html\[[^\]]+\](?:\[[^\]]+\])?)[^{]*\{([^}]*)\}", src):
    scope, body = m.group(1), m.group(2)
    vals = dict(HEX.findall(body))
    if "--bg" not in vals:
        continue                       # 색을 정의하지 않는 블록 (레이아웃 규칙 등)
    seen += 1
    floor = 7.0 if "contrast" in scope else MIN
    need = {k for pair in PAIRS for k in pair}
    missing = sorted(need - set(vals))
    if missing:
        # 이 스크립트는 같은 블록 안의 변수만 본다. 빠진 토큰은 검사 구멍이지
        # 통과가 아니다.
        print(f"{scope}: 토큰 누락 {missing} — 이 블록에서 다시 선언할 것")
        bad += len(missing)
    for fg, bgk in PAIRS:
        if fg in vals and bgk in vals:
            r = ratio(vals[fg], vals[bgk])
            if r < floor:
                print(f"{scope}: {fg} on {bgk} = {r:.2f} (< {floor})")
                bad += 1
if seen == 0:
    print("색 블록을 하나도 못 찾았다 — 정규식이나 토큰 블록을 확인할 것")
    sys.exit(1)
print(f"검사한 블록 {seen}개, 위반 {bad}건")
sys.exit(1 if bad else 0)
```

**한계와 그 대응:** 이 스크립트는 **같은 블록 안에 함께 정의된 변수만** 본다. 상속을 따라가지
않는다. 그래서 각 테마 블록이 `PAIRS` 에 필요한 토큰을 **전부 다시 선언해야 하고**, 안 하면
스크립트가 그것 자체를 실패로 보고한다 (`토큰 누락 …`). 조용히 넘어가던 것이 이번에 막혔다.

기대 출력 (`00-디자인-토큰.md` §1 의 토큰 기준):

```
검사한 블록 4개, 위반 0건
```

네 블록은 `:root` · `[data-theme="light"]` · `[data-contrast="1"]` · `[data-contrast="1"][data-theme="light"]`.
**4가 아니면 정규식이 블록 하나를 놓친 것이다** — 통과로 읽지 말 것.

### 6-1. 1,000행 대응

현행 `renderList()` 는 매번 전체를 `document.createElement` 로 만든다. 100건은 괜찮고 1,000건은 안 된다.

**상한 렌더 + 더 보기**를 쓴다. 가상 스크롤보다 단순하고 이 도구에는 충분하다.

```js
const PAGE=200;
function renderList({fast=false}={}){
  const vis=visible();
```

### 6-2. 하지 말 것

| 금지 | 이유 |
|---|---|
| 행마다 SVG 아바타 인라인 | 1,000행 × 12 `<rect>` = 12,000 노드. **아바타는 표·맵·비교에만** |

## 8. 하지 않기로 한 것

| 유혹 | 왜 안 하나 |
|---|---|
| 판정기 문구를 키로 빼기 | 로직이 바뀐다. 번역은 사전이 한다 |
| 위상 이름을 영문 열거형으로 | `paneCmp` 가 `p.k==="실행"` 으로 비교한다 |
| 프레임워크 · 번들러 | 빌드 도구 없음 · 단일 파일 |
| 차트 라이브러리 | 외부 요청 0 |
| 웹폰트 링크 | 같은 이유. 픽셀 폰트는 base64 P2 |
| 캐시·모델별 비용 화면 | 로그에 필드가 없다. 그리면 지어내는 것 |
| 실시간 모드 | 데모 리스크. 재생 모드가 그 자리 |
| 용어를 게임 어휘로 교체 | 심사위원이 화면 단어를 문서와 대조해야 한다 |
| 인접 코드 정리 | 범위 밖. 보이면 보고만 한다 |
| `viz/trace-visualizer.html` 직접 수정 | 산출물이다. `src/app.html` 을 고치고 `build.sh` 로 재생성 |
