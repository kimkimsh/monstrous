# 01. 아트 디렉션 — 따스한 도트 아케이드 계기판

이 문서는 **왜 이 방향인가**를 적는다. 정확한 값은 `../spec/00-디자인-토큰.md`.

---

## 1. 한 문장과 세 개의 금지

> **아케이드 캐비닛의 계기판.** 따스한 흑갈 바탕, 도트로 그린 계기와 캐릭터, 셀 단위 게이지, 그리고 토큰을 코인처럼 세는 크레딧 계기.

이 방향은 세 가지를 **하지 않기로 함으로써** 정의된다.

| 안 한다 | 왜 |
|---|---|
| **픽셀 폰트로 한글을 찍지 않는다** | 요구사항 "가독성 엄청 좋고"와 정면충돌. 8×8 격자에 `읽`·`웨` 를 넣으면 뭉갠다 |
| **용어를 게임 어휘로 바꾸지 않는다** | `실행`은 `실행`, `웨이브`는 `웨이브`. 심사위원이 화면 단어를 문서와 대조할 수 있어야 한다 |
| **실패를 벌칙으로 연출하지 않는다** | 실패의 상당수가 `owner: organizer` 다. "GAME OVER"는 틀린 말을 하는 화면이다 |

## 2. 색 — 340°에서 100°까지의 원호

### 2-1. 왜 따뜻해야 하나 (취향 말고)

현행은 `#0e1116` (218°, 청) 바탕에 `#4cc2ff` (199°, 시안) 액센트다. **AI:GO 대시보드를 포함해 심사위원이 그날 볼 개발자 도구 전부가 이 계열이다.** 차별화가 채점 항목인 상황에서, 색이 같으면 화면이 시작부터 "또 하나의 로그 뷰어"로 읽힌다.

따뜻한 쪽으로 옮기면 두 가지가 동시에 해결된다 — 눈에 띄고, 아케이드 캐비닛의 인광 계통(앰버·호박)과 자연스럽게 맞는다.

### 2-2. 바탕 세 층

| 역할 | 다크 | 라이트 |
|---|---|---|
| 캐비닛 바깥 (`--bg`) | `#17110E` | `#FBF1DF` |
| 패널 (`--panel`) | `#211812` | `#FFFAF0` |
| 패널 안쪽 (`--panel-2`) | `#2C201A` | `#F2E4CC` |

**중성 회색이 아니라 흑갈이다.** 순수 회색 위에 따뜻한 액센트를 올리면 액센트만 뜨고 화면은 여전히 차갑다. 바탕이 이미 따뜻해야 전체가 따뜻해진다.

### 2-3. 6색 아케이드 램프

| 이름 | 다크 | 라이트 | 색상 |
|---|---|---|---|
| EMBER | `#FF8A3D` | `#AF3B09` | 25° |
| GOLD | `#FFC24B` | `#865A00` | 40° |
| LIME | `#B5D94A` | `#3F6A0B` | 74° |
| CORAL | `#FF6B5E` | `#B92D24` | 5° |
| MAGENTA | `#FF7FB8` | `#B12B75` | 335° |
| PLUM | `#C08CE0` | `#7A3DAF` | 279° |

**전부 4.5:1 이상**을 만족한다. 하한은 **자기 배경 중 가장 어두운 것**, 즉 `--panel-2` 기준이다 —
다크 5.66 ~ 9.84, 라이트 4.82 ~ 5.38. 검증표는 `../research/04-아트-레퍼런스-조사.md` §4.

> 라이트 값은 한 번 다시 뽑았다. 첫 산출이 `--bg` 만 보고 정한 값이라 CORAL 이 `--panel-2`
> 위에서 4.49:1 이었다. **최악 배경은 `--bg` 가 아니라 `--panel-2` 다.**

PLUM만 원호를 벗어나므로 **여섯 번째 계열색으로만** 쓴다. 판정색으로는 안 쓴다.

### 2-4. 색 3층 규약 — 이번 개편의 가장 중요한 규칙 하나

현행의 구조적 결함: 트랙색과 상태색이 같은 변수를 공유한다.

```js
// app.html:559-563 — coding 이 --accent, math 가 --ok 를 쓴다
coding :{label:"coding",  contract:"patch",  c:"var(--accent)"},
math   :{label:"math",    contract:"boxed",  c:"var(--ok)"},
```

목록 한 행에 트랙 배지와 판정 배지가 나란히 서면 **같은 초록이 "math"와 "적격" 두 뜻을 갖는다.** clarity가 여기서 무너진다.

새 규약:

| 층 | 무엇에 | 규칙 |
|---|---|---|
| **1. 판정색** | 채점 적격 / 답 형식 없음 / 실행 불가·계약 미전송 / 판정 보류 | **꽉 찬 배경 + 어두운 잉크.** 어디서나 같은 뜻. 4색 고정 |
| **2. 계열색** | 스쿼드·워크스페이스 구분 | 6색 램프를 순서대로. **차트와 목록 왼쪽 세로 막대에만** |
| **3. 트랙** | coding / math / generic / unknown | **색을 안 쓴다.** 얇은 테두리 + 도트 글리프 + 라벨 |

**트랙에서 색을 뺀 것이 핵심 결정이다.** 대신 글리프로 구분한다.

| 트랙 | 글리프 | 계약 |
|---|---|---|
| coding | `</>` (도트 3×5 꺾쇠) | `*** PATCH START ***` … `*** PATCH END ***` |
| math | `∑` (도트 5×5) | `FINAL ANSWER: \boxed{…}` |
| generic | `A?` (도트 5×5) | `ANSWER: <letter>` |
| unknown | `?` | — |

예외 하나: **「트랙별」 카드와 트랙 분해 차트 안에서는** 계열색 램프를 빌려 쓴다. 그 문맥에는 판정 배지가 같이 나오지 않으므로 충돌하지 않는다. 이 예외는 스펙에 명시한다.

### 2-5. 판정 4색

| 판정 | 색 | 왜 |
|---|---|---|
| 채점 적격 | LIME | 유일하게 점수가 되는 상태 |
| 답 형식 없음 | CORAL | **우리가 프롬프트로 고칠 수 있는 영역** |
| 실행 불가 · 계약 미전송 | GOLD | 우리 밖 또는 러너 쪽. 경고이지 실패가 아니다 |
| 판정 보류 | 중성 (`--fg-faint` 배경) | 모르는 것에 색을 주면 안다는 뜻이 된다 |

**"답 형식 없음"만 빨강인 것이 의도다.** 네 갈래 중 우리가 손댈 수 있는 하나를 색으로 지목한다.

## 3. 형태 — 도트를 폰트 없이 만드는 여덟 가지

| 수단 | 규칙 |
|---|---|
| **4px 격자** | 모든 간격·크기가 4의 배수. 예외 없음 |
| **하드 엣지** | `border-radius: 0`. 유일한 예외는 원형 점(에이전트 상태) |
| **1px 오프셋 블록 그림자** | `box-shadow: 3px 3px 0 색` — 블러 없음. 도트 UI의 입체는 계단이다 |
| **셀 게이지** | 진행률을 연속 막대가 아니라 칸으로. 칸 사이 2px 간격 |
| **인라인 SVG 도트 아트** | 로고·아바타·글리프·도장. 4px 격자 `<rect>` 로만 |
| **`steps()` 이징** | 게이지·카운터·깜빡임 |
| **디더 패턴** | `repeating-linear-gradient` 45°. 비활성·미참여 영역 |
| **스캔라인** | 2px 주기, 불투명도 4%. 캐비닛 바깥 영역에만 |

### 3-1. 도트 아바타 5종

`.squad.json` 의 로스터가 고정돼 있다 (`../research/02` §5-1). 역할별 12×12 도트 아바타를 그린다.

| 역할 | 이모지(폴백) | 도트 모티프 | 색 |
|---|---|---|---|
| Planner (Router) | 🗺 | 갈림길 화살표 | GOLD |
| Architect | 📐 | 직각자·격자 | MAGENTA |
| Developer (Editor) | 🔧 | 렌치·볼트 | EMBER |
| Solver | 🧮 | 주판알 3개 | LIME |
| Reviewer | 📤 | 도장·체크 | PLUM |
| (알 수 없음) | `icon` 값 그대로 | — | 중성 |

**`.squad.json` 이 없거나 다른 스쿼드면 이모지로 폴백한다.** 도트 아바타는 다섯 역할에만 매핑되고, 없는 역할에 억지로 그림을 주지 않는다.

아바타는 스쿼드 맵·로스터 표·재생 레인·비교 화면에서 **같은 그림**으로 재사용한다. 같은 캐릭터가 네 화면에 나오면 화면이 하나의 물건으로 묶인다.

### 3-2. 판정 도장

현행에 이미 `GRADED` / `NOT GRADED` 도장과 `stamp-in` 애니메이션이 있다. 이건 좋은 자산이라 **살리고 강화한다.**

- 사각 도트 테두리 + 안쪽 디더
- 회전 -4°, 팝 진입 (오버슈트 12%)
- **한국어 라벨이 주, 영문이 보조.** `채점 적격` 크게 / `GRADED` 작게

## 4. 시그니처 — 크레딧 계기

이 화면이 기억될 하나.

```
┌──────────────────────────────────────────────────────┐
│ CREDITS  1.24M  ███████████░░░░░░       1칸 = 100k tok│
└──────────────────────────────────────────────────────┘
```

**왜 이것인가:**

1. **토큰 효율이 30점짜리 독립 축이고, 40점 축의 동점 처리 1순위다.** 화면의 주인공 자리를 줄 만하다.
2. **"토큰"은 원래 아케이드 코인을 뜻하는 말이다.** 은유를 새로 지어낸 것이 아니라 이미 있는 말이다.
3. **상호작용의 종점이 된다.** 낭비 사분면 슬라이더를 끌면 이 계기가 실제로 줄어든다. 심사위원이 만지는 손과 화면 맨 위 숫자가 연결된다.

**정직성 규칙 셋:**

- 칸은 보조 표기다. **실제 토큰 수를 항상 병기한다.**
- 환산 비율을 계기 옆에 항상 적는다. **비율은 총량에서 유도한다 — 고정 숫자가 아니다.**
  (한때 `1칸 = 1,000 토큰` 으로 적혀 있었는데 100배 틀린 값이었다. 총량 1.24M 에 20칸이면
  칸당 62k, 올림해서 100k 다. 유도식은 `../spec/03-화면별-스펙.md` §1-1.)
- 절단선 실험 중에는 **원래 값을 희미한 칸으로 남긴다.** 줄어든 것과 원래 값이 동시에 보여야 실험이 실험으로 읽힌다.

**이것 하나에만 대담함을 쓴다.** 나머지는 조용하고 규율 있게.

## 5. 타이포그래피 — 도트 방향에서 가장 조심할 곳

### 5-1. 세 가지 역할, 세 가지 글꼴

| 역할 | 글꼴 | 어디에 |
|---|---|---|
| **본문 · UI** | Pretendard → Apple SD Gothic Neo → Malgun Gothic → Noto Sans KR | 문장, 라벨, 표 |
| **숫자 · 원문 · 코드** | `ui-monospace` 계열 + `tabular-nums` | 숫자 열, 요청·응답 원문, 마커 |
| **HUD 라벨** | 모노 대문자 + `letter-spacing: .16em` | `CREDITS` · `WAVE 2/3` · `GRADED` |

**현행은 본문 전체가 고정폭이었다.** 스택에 한글 글리프를 가진 폰트가 없어 한글만 폴백되고, 라틴은 고정폭 한글은 비례폭이 되어 한 줄 안에서 리듬이 깨졌다. 화면 문구가 대부분 한국어인 도구에서 이건 선택이 아니라 사고다.

### 5-2. 7단 스케일

14종을 7단으로 줄인다. 값은 `../spec/00-디자인-토큰.md` §3.

| 단 | 용도 |
|---|---|
| `display` | 크레딧 계기 숫자, 결론 한 줄 |
| `title` | 패널 제목 |
| `lead` | 패널의 질문 한 줄 |
| `body` | 본문, 표 셀 |
| `label` | HUD 라벨, 배지 |
| `caption` | 각주, 눈금 |
| `micro` | 차트 안 최소 라벨 |

**`caption` 이 하한이고 `micro` 는 차트 SVG 안에서만 쓴다.** 지금처럼 9px 각주가 본문 옆에 붙는 일이 없다.

### 5-3. 픽셀 폰트는 선택 항목

라틴 대문자 전용 픽셀 폰트를 base64로 넣으면 HUD가 더 아케이드다워진다. 하지만:

- 기본 설계는 **폰트 없이 성립해야 한다.**
- 켤 때는 `--font-display` 하나만 바꾼다.
- 한글은 어떤 경우에도 이 폰트로 안 찍는다.
- 예산 27KB (base64 기준).

라이선스가 확인된 폰트를 확보하기 전에는 켜지 않는다.

## 6. 모션 — "많다"는 인상을 어디서 만드나

요구사항의 "애니메이션이 많고"와 "한눈에 쉽게 파악"은 정면으로 부딪친다. 빈도로 나눠서 푼다.

| 빈도 | 예 | 방침 |
|---|---|---|
| 하루 수백 번 | `j`/`k`, 탭 전환, 검색 타이핑 | **애니메이션 0** |
| 수십 번 | 호버, 프레스, 필터 | 100~160ms 색·스케일만 |
| 가끔 | 모드 전환, 실행 선택, 패널 진입 | 180~260ms |
| 드물게 | 오프닝, 재생, 판정 도장, 슬라이더 결과 | **여기에 전부 쓴다** |
| 상시(주변) | 스캔라인, 간선 흐름, 실행 중 맥동 | 저진폭·저주파 |

**"많다"는 인상은 드물게·상시 두 층이 만든다.** 고빈도 경로는 지금보다 오히려 덜 움직인다 — 현행은 `j`/`k` 마다 카드 전체가 220ms 진입 애니메이션을 재시작한다.

시그니처 이징 하나로 80%를 처리한다.

```css
--ease:      cubic-bezier(0.23, 1, 0.32, 1);    /* 진입 */
--ease-pop:  cubic-bezier(0.34, 1.4, 0.5, 1);   /* 도장·팝 (오버슈트 12%) */
--ease-move: cubic-bezier(0.77, 0, 0.175, 1);   /* 화면 안 이동 */
```

**`ease-in` 은 UI에 쓰지 않는다.** 시작이 느려서 같은 시간이어도 느리게 느껴진다.

### 6-1. 계단이 정체성이다

일반 UI는 부드러운 보간이 정답이지만, 도트 화면에서는 `steps()` 가 성격을 만든다. 셀 게이지가 칸 단위로 켜지고, 카운터가 계단으로 오른다. **다만 도장과 패널 진입은 부드럽게** — 찍히는 감각은 매끄러워야 무게가 산다.

### 6-2. 오케스트레이션 하나

한 번만 크게 연출한다: **폴더를 놓은 직후.**

```
0ms    캐비닛 바깥이 어두워진다
120ms  HUD가 위에서 내려온다 (--ease, 220ms)
240ms  계기 4개가 60ms 간격으로 켜지고 숫자가 steps(12) 로 카운트업
420ms  좌측 실행 목록이 위에서부터 40ms 간격으로 쌓인다 (최대 12행까지만 stagger)
680ms  스캔라인이 켜진다
```

총 700ms 안에 끝난다. **이후로는 이 시퀀스가 다시 재생되지 않는다** — `폴더 다시 고르기` 를 눌렀을 때만.

## 7. 이 방향이 실패하는 시나리오와 방어선

| 실패 | 징후 | 방어선 |
|---|---|---|
| 예쁜데 질문에 답 못 함 | 패널에서 질문 한 줄이 사라짐 | 질문 줄은 모든 패널의 **첫 요소**. 어떤 장식도 그 위에 오지 않는다 |
| 도트가 글자를 먹음 | 라벨이 안 읽힘 | 픽셀은 SVG 그림 전용. 텍스트에는 어떤 픽셀 효과도 안 건다 |
| 색이 뜻을 잃음 | 같은 색이 두 뜻 | 색 3층 규약 (§2-4) |
| 실패를 놀림 | `owner: organizer` 에 벌칙 연출 | 실패 연출 금지 |
| 모션 멀미 | 시연 중 산만 | 발표 모드에서 주변 모션 감쇠 + `prefers-reduced-motion` |
| 아기자기함이 유치해짐 | 심사 자리에서 가벼워 보임 | **숫자는 항상 정직하고 크게.** 캐릭터는 작게, 데이터는 크게 |

마지막 항목이 이 방향의 진짜 위험이다. 규칙 하나로 요약한다.

> **캐릭터는 데이터보다 커지지 않는다.**
> 도트 아바타 12px. 숫자는 자리에 따라 두 단이다 — **HUD 안에서 20px, 화면 본문의 결론 자리에서
> 32px.** HUD 계기를 32px로 두면 상단 바가 90px로 부풀어 §5-1의 절약이 사라진다
> (`../spec/01-컴포넌트-스펙.md` §16-0). 어느 쪽이든 **같은 화면에서 가장 큰 것은 언제나 숫자다.**
