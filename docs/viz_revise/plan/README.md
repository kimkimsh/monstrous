# viz_revise / plan — 개선 기획

`viz/` 시각화 프로그램의 **UX·UI 전면 재작성** 기획이다.

전제 하나: **기능은 살리고 화면만 갈아엎는다.** 파싱·판정·집계·재생 시계·로드 파이프라인은 한 글자도 안 건드리고, `<style>` 383줄과 렌더 계층 약 2,600줄을 새로 쓴다. 그 경계선은 `../research/00-현행-viz-해부.md` 가 줄 번호로 확정해 두었다.

## 읽는 순서

| 문서 | 무엇을 정하나 |
|---|---|
| **`00-기획안.md`** | 왜 다시 만드는가 · 무엇을 살리고 무엇을 버리는가 · 성공 조건 · 위험 |
| **`01-아트-디렉션.md`** | 색·타이포·형태·모션의 방향과 **시그니처 하나**. 왜 이 선택인지, 무엇을 버렸는지 |
| **`02-화면-설계.md`** | 화면별 정보 구조와 배치. ASCII 와이어프레임 |
| **`03-이행-계획.md`** | 어떤 순서로 바꾸고, 무엇으로 다 됐다고 판단하는가 |

스펙(실제 값)은 `../spec/` 에 있다. **기획은 "왜"와 "무엇을", 스펙은 "얼마나"를 적는다.** 값이 두 곳에 있으면 스펙이 정본이다.

## 한 장 요약

| 항목 | 결정 |
|---|---|
| 범위 | `viz/src/app.html` 의 `<style>` · 정적 마크업 · 렌더 계층 |
| 보존 | 로직·인프라 약 1,150줄. **반환 구조와 문자열까지 바이트 동일** |
| 방향 | 따스한 도트 아케이드 계기판. 색상 원호 340°~100° |
| 시그니처 | **크레딧 계기** — 토큰을 칸으로 세고, 절단선 슬라이더가 실시간으로 깎는다 |
| 노리는 점수 | 시각화 30점 중 **clarity · insightfulness** 두 축 |
| 지키는 하한 | 텍스트 명암비 **4.5:1**, 타입 스케일 **7단**, 고빈도 조작 애니메이션 **0** |
| 깨면 안 되는 것 | 단일 파일 · 외부 요청 0 · 재생 모드 · 한/영 전환 · URL 상태 · 고대비/발표/인쇄 · SVG/JSON 내보내기 |
