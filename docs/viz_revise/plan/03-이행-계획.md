# 03. 이행 계획 — 순서·검증·완료 판정

---

## 1. 원칙 — 한 번에 다 갈아엎지 않는다

렌더 계층 2,600줄을 한 커밋에 바꾸면 **판정 숫자가 달라졌을 때 어디서 달라졌는지 못 찾는다.** 그래서 다섯 단계로 자르고, **각 단계 끝마다 회귀 검사를 돌린다.**

회귀 검사의 기준선은 하나다.

> **같은 워크스페이스를 넣고 `JSON` 내보내기를 눌렀을 때, 개편 전후의 파일이 바이트 동일해야 한다.**

`btn-json` 이 내보내는 것은 실행 id·워크스페이스·계약·`gradable`·`blocker`·토큰·위상·태스크별 검사 결과 전부다 (`app.html:3737-3757`). **이게 같으면 로직을 안 건드린 것이고, 다르면 건드린 것이다.** 화면이 아무리 바뀌어도 이 파일은 안 바뀐다.

먼저 기준선을 뜬다.

```bash
# 개편 전. 세 워크스페이스를 넣고 JSON 내보내기 → baseline.json 으로 보관
cp ~/Downloads/monstrous-normalized.json docs/viz_revise/research/baseline-normalized.json
```

## 2. 단계

### P0 — 계산 추출 (렌더를 건드리기 전)

렌더 함수 안에 숨어 있는 계산을 순수 함수로 끌어낸다. **이 단계에서는 화면이 하나도 안 바뀐다.**

| 추출 | 새 함수 | 현 위치 |
|---|---|---|
| 판정 가능 분모 | `decidable(execs)` | `renderHeader` 1903 · `runSummaryCard` 1993 |
| 절단선 결과 | `cutResult(execs, cut)` | `drawWaste` 2348-2359 |
| 답 근접도 | `nearness(exec)` | `drawNear` 2389-2399 |
| 큐 대기 | `waitOf(task)` + `WAIT_WARN_MS = 10000` | `paneOverview` 2069 · `paneTimeline` 3257 |
| 스쿼드 통계 | `squadStat(squad)` | `paneCmp` 2444-2450 |
| 같은 요청 묶기 | `sharedRequests(execs)` | `sameRequestCard` 2512-2519 |
| 맵 열 구성 | `mapLayout(exec)` | `squadMap` 2954-3010 |
| 재생 시계 | `replayState(exec, t)` | `paneReplay.frame` 2852-2947 |

**검증:** JSON 내보내기 바이트 동일 + 화면 육안 무변화.

### P1 — 토큰과 뼈대

`<style>` 전면 교체 + HUD 1층 구조. **탭 내용은 아직 옛 렌더 함수를 그대로 부른다.**

이 단계에서 화면은 "새 색·새 타이포에 옛 내용"이 된다. 어색하지만 **색·간격·타이포 체계가 실제 데이터 위에서 맞는지**를 여기서 확인한다.

체크:
- 텍스트 명암비 전 토큰 4.5:1 이상 (스크립트로 검사, `../spec/04` §5)
- 글자 크기 7종만 사용
- `border-radius` 0 (원형 점 예외)
- 인라인 `style="…"` 개수 88 → **20 이하**

### P2 — 실행 하나 모드

개요 → 재생 → 장부 대조 → 타임라인 → 실패 분류 → 원문 로그 순으로 하나씩.

각 탭이 끝날 때마다:
- 그 탭의 모든 데이터 분기를 실제 워크스페이스 3곳으로 확인 (적격 / 형식없음 / 호출거부 / 계약 미전송 / 판정 보류)
- `i18nAudit()` 이 그 탭에서 0을 돌려주는지

### P3 — 전체 분석 · 스쿼드 비교

절단선 실험대 승격이 여기 들어간다. **HUD 크레딧 계기 연동**이 이 단계의 핵심이고, 회귀 위험이 가장 크다 (슬라이더 → 계기 → 재렌더 루프).

### P4 — 오프닝 · 상태 모드 · 마무리

오프닝 도트 연출, 발표·고대비·인쇄 모드, 단축키 도움말 패널(`alert` 제거), `build.sh` 검사 추가.

## 3. 각 단계의 공통 게이트

단계를 넘어가기 전에 전부 통과해야 한다.

| # | 게이트 | 방법 |
|---|---|---|
| 1 | JSON 내보내기 바이트 동일 | `diff baseline-normalized.json new.json` |
| 2 | `bash viz/tools/build.sh` 통과 | 외부 요청 0 · 잔재 마커 0 |
| 3 | 콘솔 에러 0 | 세 워크스페이스 × 3모드 × 6탭 |
| 4 | `i18nAudit()` == 0 | 영어 모드에서 |
| 5 | URL 해시 왕복 | 링크를 새 창에 붙여 같은 화면이 나오는가 |
| 6 | 단축키 9개 동작 | `j k 1-6 m / b ? Esc` + 방향키 |

## 4. 완료 판정

### 4-1. 로직 무결성 — 반드시

- [ ] `JSON` 내보내기가 개편 전과 **바이트 동일**
- [ ] `app.html:539-1278` · `3369-3504` · `3711-3758` 구간의 diff가 **0줄**
- [ ] `checks[].k` / `.d` 문자열 무변경
- [ ] `phasesOf` 반환 위상 이름 무변경 (`"플래닝"` · `"승인 대기"` · `"실행"` · `"집계"`)

### 4-2. 결함 해소 — 측정으로

| 결함 | 목표 | 측정 |
|---|---|---|
| B-1 명암비 3.25:1 | **모든 텍스트 토큰 ≥ 4.5:1** | 검사 스크립트 |
| A-1 글자 크기 16종 | **7종** | `grep -o 'font-size:[0-9.]*px'` |
| A-2 반지름 8종 | **1종 (0)** + 원형 예외 | 같은 방법 |

## 5. 데이터 검증 — 반드시 이 다섯 상태를 다 본다

한 상태만 보고 "된다"고 하면 안 된다. 각 상태의 실제 워크스페이스가 저장소에 있다.

| 상태 | 어디서 | 무엇을 확인 |
|---|---|---|
| **채점 적격** | `squad/test` 일부 | 도장 · 강조 구간 · 검사 4개 통과 |
| **답 형식 없음** | `squad/test_2` | CORAL 도장 · 근접도 · `artifacts` 경고 |
| **호출 거부** | `squad/ikkim` 일부 | GOLD 도장 · `context_overflow` · 토큰 0 |
| **계약 미전송** | `squad/ikkim` 6건 | GOLD 도장 · "지문에 절이 없음" |
| **판정 보류** | 계약 불명 실행 | 중성 도장 · **불합격으로 안 적히는지** |

추가로:

| 경계 | 확인 |
|---|---|
| 워크스페이스 1개만 | 스쿼드 비교 모드의 안내 · 필터 숨김 |
| 워크스페이스 3개 | 계열색 3종 · 같은 문항 비교 |
| 한 워크스페이스에 스쿼드 4개 | `squadId` 로 갈리는지 (`squad/ikkim`) |
| `.squad.json` 없음 | 로스터 추론 + `(플래너)` 자리 |
| 에이전트 7명 | 맵 열 접기 (4개 초과) |
| `tasks/*.json` 없음 | 대기·우선순위·시도 열이 `—` |
| 부분 기록 | `history.json` 에 없는 실행 |

각 단계를 별도 커밋으로 둔다. 문제가 생기면 그 커밋만 되돌린다.

## 8. 하지 않기로 한 것 — 다시 확인

작업 중에 하고 싶어지는 것들이다. 하지 않는다.

| 유혹 | 왜 안 하나 |
|---|---|
| 판정기 문구를 키로 빼기 | 로직이 바뀐다. 번역은 사전이 이미 한다 |
| 위상 이름을 영문 열거형으로 | `paneCmp` 가 `p.k==="실행"` 으로 비교한다 |
| 프레임워크 도입 | 빌드 도구 없음 · 단일 파일 |
| 차트 라이브러리 | 외부 요청 0 |
| 캐시·모델별 비용 화면 | 로그에 필드가 없다 |
| 실시간 모드 | 데모 리스크. 재생 모드가 그 자리 |
| 용어를 게임 어휘로 교체 | 심사위원이 문서와 대조할 수 있어야 한다 |
| 인접 코드 정리 | 범위 밖. 보이면 보고만 한다 |
