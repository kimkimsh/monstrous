01 The shape · why not one

One seat the app forced. One seat arithmetic asked for.

The planner seat is nailed downplatform

Only the planner sees the request in full. Workers receive the description of the task the planner wrote and nothing else. We cannot delete the seat, so we shrank its job: Router calls create_task once and stops.

Coder and Solver split on lengtharithmetic

Coder's contract runs to 7,698 characters, of which 1,943 are the patch format the parser enforces. Merge the two seats and every math item carries those rules past a parser it will never reach.

A merge would charge 109 of 147 items
Coding request, median 63,812 B across the 20 published coding requests

Head count multiplies the damage when the planner call fails. If it does, the app stops splitting the request and hands the full text to every non-planner seat. Each extra seat then costs another full copy of that median on a single coding item.

Monstrous Squad05
02 The contracts · Router

Router. One create_task call, and then it stops.

The block decides the tracknot the model
What the REQUIRED OUTPUT block asks forGoes to
A patch between two patch markersCoder · coding
A final boxed valueSolver · math
A single option letterSolver · generic
Something else, or no block at allSolver · other

The rule reads the shape of the block, so there is no room for the model to guess a track. The composer only ever appends one of the first three; the fourth row is our own guard against a shape we have not seen.

Never calls check_task_status · aggregate_results · update_plan
It copies; it does not summarise

A rewritten problem is a different problem. An options list that was not copied has no letter to choose. A retyped source line is a patch that will not apply.

Coding is the one exception

Repository context runs to about 60,000 characters and will not fit. The REQUIRED OUTPUT block goes first — it is last in the request and first in the copy — then the issue text, then excerpts strongest-first. It stops at 32,000 characters and drops a whole excerpt rather than cutting one.

Excerpt ranking, strongest first
  1. A path the issue names outright
  2. A path in the traceback the issue pasted
  3. An excerpt defining a symbol the issue called
  4. An excerpt calling that symbol

Anything past the fourth is a guess, and one guess spends about 12,000 characters.

02 The contracts · Coder

A patch that does not apply is worth zero, however right the fix was.

What the patch parser enforceseach row turns a correct fix into 0
RuleWhat breaking it does
The three inner markers start at column 0 One leading space parses the whole patch into zero blocks
SEARCH matches the file byte for byte One different quote or one space of indent and it will not attach
SEARCH is unique within that file Two matches and nothing attaches. Widen with surrounding lines
No prose between blocks Read as the next block's path line. The patch stops with no error
No anchor line of seven or more = The parser ends SEARCH there. Again, no error. Runs of < or > are safe unless the line spells out  REPLACE
One patch per reply Only the last is read, so a second attempt buries a good first one
No unified diff, no git diff, no whole-file rewrite Nothing is extracted, so the item scores zero
The only shape that is read
*** PATCH START ***
path/to/file.py
<<<<<<< SEARCH
    the exact lines now in the file
=======
    the lines that replace them
>>>>>>> REPLACE
*** PATCH END ***
When several paths reach the same function, the fix belongs in that function once. Patching only the path the issue named is the larger change and the one that leaves a sibling broken, and the tests that already pass are checking that sibling.
No tools, by design

Coder cannot open a file, run a test, or search the repository. A path, symbol or line number absent from the text it was handed is invented, and an invented patch does not apply.

Monstrous Squad08
02 The contracts · Solver

Solver carries 109 of 147 items.

Mathematics

Solve to a value, then check it a second way — substitute back, re-derive one step along another path, or try the smallest case. When the two disagree, take the one you can justify.

No averaging, and never both answers. Sign, integrality, range, and extraneous roots get checked.

Multiple choice

Solve before looking at the options. Picking an option first and reasoning towards it is how a wrong option wins.

Option counts run from three to ten, so the list may stop at C or at G. A letter past the end of that item's own Options block scores zero however good the reasoning.

Everything else

Three benchmarks are graded, but the harness can send something outside them. A squad that knows only three tracks forces a shape onto the fourth and loses a correct value to formatting.

There, the contract is whichever sentence the request uses to state its own answer shape.

Three ways the letter line breaks
the letter pattern is anchored to the whole line; the boxed pattern is not
Before the value
bold marks, a bullet, a quote arrow
After the value
an option name, brackets, a full stop, two letters
In the wrong case
the pattern is anchored to the whole line
Monstrous Squad09
02 The contracts · who verifies

We did not delete the verifier. We moved it into two places.

Inside the agent's own turnno extra call
  • Solver's second derivation of the same value
  • Coder's sibling-caller check before it writes
  • The final-line rules, applied by the seat that writes the line

All of it runs inside one response, so the call count does not move.

Model calls added0
A program, at build timetools/validate_template.py

The build feeds our six prompt texts — system and task, per seat — to the grader's own extractors — extract_letter, extract_boxed, extract_patch. If any of them pulls an answer out, the check fails and nothing is submitted.

If the grader can find an answer in our instructions, then the moment a model leaks a fragment of those instructions, the fragment is what gets graded.
Conditions enforced50
Human review needed none

Why not one more verification hop. The grader reads only the last task, so a verification hop becomes the last hop, and that seat is not the one that produced the answer. Beyond that, published results we designed against: self-verification with no external signal dropped GPT-4 on GSM8K from 95.5% to 89.0%, while deterministic supervision raised SWE-bench resolve rate by 9.9% on average. Both are collected in 00-스쿼드-스펙.md §614–617. We took the second one.

Monstrous Squad10
03 Giving up, and the budget

Nothing caps the run, so giving up means not making the call.

Hidden-set caps, from the leaderboard API

no wall-clock cap,
no token cap

Both fields come back null on every graded run. Nothing throttles a run from outside, so every call we make is a call we chose.

The plan graph freezes before the run starts and carries no conditional branch, so this cannot be an agent making a judgment call. It has to be four rules, each sitting where it can still act.

01 · Router

One task, no re-planning. The app's own planner instruction says split as small as possible; we reversed it. One task is one model call.

02 · Copy budget

32,000 characters, filled strongest-first. If create_task returns a length error, drop the excerpts and call again. Issue text alone still scores; a missing task scores zero.

03 · The worker

When a derivation runs long, stop and write the answer line with the best value held so far. A truncated response has no answer line at all — the only way we lose an item already solved.

04 · Never answer empty

This one reversed. With several waves an empty output is safe, because the grader skips back. With one wave there is no net. Empty is a certain zero; a guess is sometimes right.

The budget file is not part of the submission. budget.json is a local squad budget and never reaches the evaluation server, which runs on runtime defaults (maxTasksPerPlan 20, maxAgentTurns 20, maxPlanIterations 3). That is why all four rules live in prompts rather than settings.

Monstrous Squad13
04 The viewer · the fault that never happened

The tool's most useful finding was its own miscount.

For a while the screen carried a branch called contract not sent. If the recorded request had no === REQUIRED OUTPUT === section, we read that as the runner failing to send the contract. On the folder in the demo that rule catches 13 items, and we were charging every one of them to the runner.

Evidence one · size was never the reason
Largest of the 13 64,914 chars
A contract section ~250 chars

That one carries a whole repository context and still has no contract section, so nothing was squeezed out for space. history.json stores the question, not the prompt the model was handed.

Evidence two · the model heard it

10 of 13 responses contained \boxed{}. Five went all the way to FINAL ANSWER:.

A model cannot follow a contract it was never sent. The branch described something that had not happened.

Write the log's silence down as an event and you invent a fault nobody committed. That is the one thing this tool must never do, so the branch came out.

Monstrous Squad15
04 The viewer · why the screen can be trusted

If it is not in the log, we do not draw it.

Deliberately absent

Cache hit rate is not in the log. Model names are not in the log. Per-task token counts come back zero. Confidence has no signal at all. Four gaps, four different reasons, and drawing any of them would be inventing numbers.

Labelled where it is inferred

Per-agent tokens are an estimate and the screen says so, in place, with the reason. Cut-line figures are an upper bound on loss, because every truncated run is counted as lost outright. That sentence is on the screen too.

Replay and simulation are labelled apart, on screen
Replay

“Replayed from the recorded log alone. Zero model calls.” Nothing is re-run and nothing is inferred.

The cut line

Titled An honest limit, because it assumes a run was abandoned the moment it hit the ceiling. Every truncated run counts as lost outright.

Nothing that did not run is drawn as though it ran.

Logic carried over unchanged 1,116 lines

We replaced the entire interface and changed no data. Parsing, verdicts, aggregation, loading and export were carried over unchanged, and the build diffs them against a frozen snapshot every time. One line of drift and no artifact is produced. Same folder in, byte-identical JSON out.

Monstrous Squad17
A Appendix · claims we do not make

Things that would sound good and are not true.

Not saidBecause
“This design raised our score” There is no graded result yet. What we can say is what we measured and which design decision each measurement produced
“Requests fell from 1,192 to 294” 294 is a projection: measured practice sizes multiplied by hidden item counts. The documents label it a projection too
“We have an agent that decides to give up” Not buildable. The plan graph freezes before the run and has no conditional branch
“Prefix caching saves us tokens” It saves latency. vLLM bills cache hits into prompt_tokens in full, and the vLLM docs describe the saving as prefill time, not tokens
“Coder runs at high reasoning effort” The template has no way to set effort per agent, and writing reasoning: high into a system prompt does not work either
“22 disabled tools locked the agents down” The squad execution path does not read that field. The handle that works is the empty enabledTools
“Here are per-item traces from a graded run” The portal returns a per-item status and owner, but no response text, and it is gated on item identities being released. No path to re-read a hidden response body has been confirmed. The viewer earns its keep on development runs
