## 영문판과 다른 점 하나 — 라벨 폰트

영문판은 라벨을 전부 `--font-mono` 로 찍는다. 한국어판에서 그대로 두면 깨진다.
뷰어 소스가 이미 같은 함정을 기록해 뒀다 (`viz_revise_program/src/app.html:2911-2913`):

> `--font-mono` 스택에는 한글 글리프가 없어 시스템 폴백이 전각으로 그린다 —
> 「요청  지문에서  계약을」이 된다.

그래서 `--font-label` 을 따로 뒀다.

| 쓰는 곳 | 폰트 |
|---|---|
| 라벨·표 머리·계기 이름·각주 — 한글이 섞이는 자리 | `--font-label` (= `--font-ui`) |
| 숫자·코드·형식 문자열·Router/Coder/Solver 같은 고유명 | `--font-mono` 유지 |

자간도 같이 손봤다. 영문 라벨의 `.15em` 은 한글에서 읽기 나쁘다. `--ls-label` 로 `.02em` 을 쓰고
`text-transform:uppercase` 는 뺐다. 한글에는 효과가 없고 섞인 영문만 들쑤신다.

## 문장을 쓴 방식

**영문판을 번역하지 않았다.** 번역하면 번역투가 남고, 그게 정확히 `humanize-korean` 이
잡아내는 패턴이다. 대신 원본 기획안 `../00-발표-구성.md` 의 한국어를 살리고,
덱에서 새로 늘어난 자리만 한국어로 새로 썼다.

윤문 검증은 `humanize-korean` v1.5 strict 로 돌렸다. 검사에서 제외한 것:
고유명사·모델명·수치·필드명, 그리고 한국 개발자가 실제로 영어로 말하는 용어
(토큰·프롬프트·태스크·패치·빌드·로그·웨이브·트랙·파서·wall-clock).
