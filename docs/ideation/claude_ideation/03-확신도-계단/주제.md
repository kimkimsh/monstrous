# 주제 3. 확신도 계단 — 의심스러울 때만 비싸게 (Confidence Ladder)

> **한 줄 요약**
> 모든 문항에 같은 스쿼드를 붓지 않는다. 1단은 거의 공짜로 답하고, **모델이 스스로 흔들릴 때만** 2단·3단으로 올라간다. 시각화의 주인공은 정답률이 아니라 **캘리브레이션(모델의 확신이 실제 정답률과 맞는가)**이다.

---

## 1. 왜 이 주제인가

이 트랙의 진짜 형태를 숫자로 보면 이렇다. Qwen3-30B-A3B-Instruct-2507의 공식 벤치마크 성적:

| 벤치마크 | 이 모델의 단일 호출 점수 |
|---|---|
| MMLU-Pro (= generic 트랙) | **78.4** |
| AIME25 (= math 트랙의 어려운 쪽) | **61.3** |
| LiveCodeBench v6 (= coding 트랙의 절반) | **43.2** |
| Aider-Polyglot (코드 편집 형식 준수력) | **35.6** ← 가장 약한 지점 |

**generic과 math는 모델 혼자서 이미 잘한다.** 여기에 에이전트를 더 붙여서 얻을 수 있는 것은 몇 점이고, 잃는 것은 수백만 토큰이다. 반대로 coding은 형편없고, 문항당 입력이 100배 크다.

즉 이 트랙의 설계 문제는 **"어디에 돈을 쓸 것인가"**이지 "어떤 팀을 짤 것인가"가 아니다. 그리고 그 결정은 문항 단위로 내려야 한다. 같은 generic 트랙 안에서도 쉬운 문항과 어려운 문항이 섞여 있기 때문이다.

또 하나 중요한 사실. 리더보드가 직접 경고한다.

> 평가 모델 3개 중 2개가 reasoning 모델이고, **하나는 답을 내기 전에 출력 예산의 97%를 사고 토큰에 썼다**고 측정되었다. 토큰 상한이 reasoning 스쿼드에 약 **10배** 세게 물린다.

비싼 자원은 있지만 함부로 쓰면 죽는다. **계단이 필요하다.**

## 2. 어떻게 작동하는가

### 3단 계단

```
1단  단일 호출, --no-think, 최소 출력.        비용 1
       ↓ 확신도가 낮을 때만
2단  같은 모델로 2~3회 더 샘플링 → 다수결.     비용 3~4
       ↓ 그래도 갈리면
3단  reasoning 모델 또는 --thinking-budget N.  비용 10~30
```

**대부분의 문항은 1단에서 끝난다.** 이게 절감의 전부다.

### 확신도를 어디서 얻는가 — 공짜 신호 세 개

1. **자기 보고 확신도.** 답 뒤에 `conf: 0.87` 한 줄. 출력 토큰 5개 미만.
2. **샘플 간 일치.** 2회 샘플이 같은 답이면 멈춘다. 다르면 올라간다.
3. **형식 신호.** math 문항이 `answer_format: integer`인데 수식이 나왔다 → 자동으로 다음 단계. 이건 LLM 호출이 0이다.

### 근거가 되는 최신 연구 (2025–2026)

| 방법 | 핵심 | 보고된 효과 |
|---|---|---|
| **ReASC** (Findings of ACL 2026) | 응답 수가 아니라 **증거 충분성**으로 멈춤. 1단계에서 단일 응답만으로 결판나는 문항을 걸러냄 | Gemma-3-4B / GSM8K에서 self-consistency 대비 **비용 최대 70% 감소**, 정확도 유지 |
| **CAS** (Confidence-based Adaptive Test-time Scaling) | 캘리브레이션된 확신도로 조기 종료 | 평균 샘플 수 64 → 5.19, **최대 12.33배 절감**, 정확도 동일 |
| **REFRAIN** (ACL 2026 Long) | 언제 멈출지를 sliding-window UCB로 자동 조정. 학습 불필요 | Qwen3-8B / MATH-500에서 **토큰 20~55% 감소**, 정확도 유지·향상 |
| **SeerSC** (Findings of ACL 2026) | 빠른 System 1이 먼저 엔트로피를 계산해 예산을 **미리** 정함 | 토큰 47% 감소, 지연 43% 감소 |

공통 발견 하나가 이 주제의 뼈대다. **높은 확신도 문항은 샘플을 아무리 늘려도 정확도가 거의 안 오른다(<0.2%p). 낮은 확신도 문항만 크게 오른다(49.0% → 54.5%).** 그러니 예산을 후자로 옮기는 것이 순이득이다.

> 이 문장들은 심사 피칭에서 그대로 인용할 수 있는 재료다. "감으로 줄였다"와 "2026년 ACL 논문 네 편이 같은 결론을 낸다"는 완전히 다르게 들린다.

## 3. 시각화 30점 — 캘리브레이션이 주인공

다른 팀은 정답률을 보여줄 것이다. 우리는 **모델이 자기가 맞았는지 아는가**를 보여준다.

| 화면 | 답하는 질문 | 형태 |
|---|---|---|
| **캘리브레이션 곡선** | 확신 0.9라고 말했을 때 실제로 90% 맞나 | x=자기보고 확신도 구간, y=실제 정답률. 대각선이 완벽. **곡선이 대각선에서 벗어난 만큼이 우리가 낭비하거나 놓친 곳** |
| **계단 이동 흐름** | 문항들이 어느 단계까지 올라갔나 | Alluvial(강물) 다이어그램. 1단 → 2단 → 3단으로 흘러가는 폭이 곧 비용 |
| **임계값 슬라이더** | 문턱을 여기 두면 어떻게 되나 | 확신도 문턱을 끌면 정확도·총비용이 실시간으로 움직인다 |
| **파레토 경계** | 우리 설정은 최적 곡선 위에 있나 | 정확도-비용 평면에 모든 설정 조합을 점으로. 우리 선택을 강조 |
| **후회 지도** | 올려봤자 안 바뀐 문항 | 3단까지 갔는데 답이 1단과 같았던 문항 = 순수 낭비. 색으로 표시 |

**캘리브레이션 곡선은 이 대회 화면 중 유일하게 "모델의 자기 인식"을 그린 그림이 된다.** 심사위원은 스쿼드 대시보드는 매일 보지만 이건 안 본다.

## 4. 세 축에 어떻게 꽂히나

- **벤치마크 40점** — 아낀 토큰을 coding으로 옮긴다. coding 가중치가 0.5이므로 같은 총예산에서 총점이 오른다.
- **토큰 효율 30점** — 위 논문들의 절감 폭(2~12배)이 그대로 우리 숫자가 될 여지가 있다. 실측으로 증명한다.
- **시각화 30점** — 캘리브레이션과 파레토 경계. 채점 구조를 정면으로 그린 화면.

## 5. 리스크와 솔직한 한계

| 리스크 | 내용 | 대응 |
|---|---|---|
| 자기 보고 확신도가 부정확할 수 있다 | 위 논문들도 "캘리브레이션이 전제"라고 명시한다. 학습 없이 쓰는 확신도는 과신 경향이 있다 | 자기 보고를 **단독으로 믿지 않는다.** 샘플 간 일치도와 형식 신호를 함께 쓴다. 그리고 그 부정확함 자체를 캘리브레이션 곡선으로 **화면에 드러낸다** — 숨기지 않는 것이 오히려 점수다 |
| 다중 샘플링이 wall-clock 캡을 건드린다 | 문항당 시간 상한이 있다 | 2단은 병렬로. AI:GO `Max concurrent agents` 기본 3 |
| reasoning 모델이 3단에서 캡을 터뜨린다 | 출력의 97%를 사고에 쓰는 모델이 있다 | 3단은 반드시 `--thinking-budget N`으로 상한을 건다. 켜고 끄는 이분법보다 낫다 |
| 계단 판단 자체가 호출을 늘린다 | 라우팅 오버헤드 | 판단을 **가능한 한 프로그램으로.** 형식 신호와 샘플 일치는 LLM 호출이 0이다 |

## 6. 확인해야 할 것

- 나머지 reasoning 모델 2개의 **정확한 이름과 단가.** 3단의 비용을 모르면 계단을 설계할 수 없다.
- `--thinking-budget`이 평가 스택에서 실제로 먹히는가 (llama-server / mlxcel-server / continuum-router 패스스루).
- 연습 세트 364문항으로 **확신도 구간별 실제 정답률**을 먼저 측정할 것. 이 표가 없으면 문턱값은 추측이다.

## 7. 추가 조사 — 계단(cascade)은 이미 검증된 구조다

3절의 논문들이 "한 모델 안에서 언제 멈출까"를 다뤘다면, 아래는 "어느 모델로 보낼까"를 다룬 계보다. 둘을 합치면 이 주제가 완성된다.

| 방법 | 구조 | 보고된 효과 |
|---|---|---|
| **FrugalGPT** (Chen·Zaharia·Zou, arXiv:2305.05176, **TMLR 2024**) | 싼 모델 → 비싼 모델 캐스케이드. 답의 품질을 **DistilBERT 하나**로 채점해서 통과/승급 결정 | **GPT-4와 같은 정확도를 최대 98% 싸게.** HEADLINES에서 $33.1 → $0.6 (98.3% 절감). **전체 질의의 16.6%만 GPT-4로 올라감** |
| **RouteLLM** (LMSYS·UC Berkeley, arXiv:2406.18665, **ICLR 2025**) | 질의별 강·약 모델 라우팅. Chatbot Arena 선호 데이터로 학습 | MT Bench에서 **비용 85% 절감, 성능은 GPT-4의 95% 유지**. MMLU 45%, GSM8K 35% 절감 |

**FrugalGPT의 구조가 이 주제에 그대로 들어온다.** 판정자가 LLM일 필요가 없다는 점이 특히 중요하다 — DistilBERT급 작은 분류기 하나면 되고, 우리 경우엔 그것마저 **형식 검사와 샘플 일치도**로 대체할 수 있다.

라우팅이 작동하는 근본 이유도 FrugalGPT가 짚었다. **어떤 모델도 전 영역에서 우월하지 않다.** 싼 모델이 비싼 모델과 **똑같은 답을 내는 질의가 87%**이고, 심지어 **더 나은 답을 내는 질의가 5%** 있다. 그래서 92%를 싼 쪽으로 보내는 것이 비용도 싸고 정확도도 높다.

## 8. 중요한 방향 수정 — 검증자보다 다수결이 낫다

이 주제를 짜다 보면 "3단에 강력한 Verifier(검증 에이전트)를 두자"는 유혹이 생긴다. **예산이 제한된 상황에서는 그게 틀렸다는 실측이 있다.**

**"When To Solve, When To Verify"** (arXiv:2504.01005):

> **고정된 추론 예산 아래에서는, 대부분의 실용적 예산 구간에서 단순 다수결(Self-Consistency)이 생성형 보상모델(GenRM) 기반 best-of-N을 이긴다.**
> GenRM이 다수결을 **따라잡는 데만 최대 8배의 연산**이 들고, 거기서 **3.8%를 더 얻으려면 추가로 128배**가 필요하다.

스케일링 법칙까지 제시한다: `S_opt ∝ C^0.57`, `V_opt ∝ C^0.39`.
→ **해(solution)를 검증(verification)보다 1.5~2배 빠르게 늘려라.**

Llama·Qwen, 7B·70B, 그리고 thinking 모델(QwQ-32B)에서 모두 성립한다.

### 그래서 계단의 2단을 이렇게 바꾼다

```
(수정 전)  2단 = 답 1개 생성 + Verifier 에이전트가 검사
(수정 후)  2단 = 답 2~3개 병렬 생성 + 다수결.   Verifier 없음.
```

**검증 예산을 생성 예산으로 옮긴다.** 같은 토큰으로 더 정확하다.

### 단, 다수결에도 함정이 있다

NeurIPS 2025 "Provable Scaling Laws for the Test-Time Compute of LLMs"가 짚은 실패 모드:

- **불완전한 검증자를 쓴 best-of-N은 샘플이 늘수록 정확도가 *떨어질* 수 있다** — 검증자를 속이는 답을 찾아내기 때문.
- **다수결은 0%로 수렴할 수 있다.** 정답이 45% 확률로 나오고 특정 오답이 46% 확률로 나오면, 샘플을 늘릴수록 나빠진다.

→ **다수결 결과를 그대로 믿지 말고, 형식 검사(결정론적)를 항상 마지막에 통과시킬 것.** 그리고 이 실패 모드 자체가 시각화 재료다: "샘플을 늘릴수록 나빠진 문항"을 따로 모아 보여주면 그 화면 하나가 `insightfulness`다.

## 9. 사고 강도(reasoning effort)에 대한 실측

3단에서 reasoning 모델을 쓸지 말지의 판단 재료다.

- **HAL (Princeton, arXiv:2510.11977)**: 사고 강도를 올린 **36개 실행 중 21개에서 정확도가 개선되지 않았다.** 강도를 올리는 것이 기본값이 되어서는 안 된다는 뜻이다.
- 반대 방향의 실측도 있다. ARC Prize 리더보드의 Opus 4.5 thinking budget 스윕: `None 7.8% @ $0.22 → 1K 9.4% @ $0.23 → 8K 13.9% @ $0.48 → 16K 22.8% @ $0.79 → 32K 30.6% @ $1.29 → 64K 37.6% @ $2.40`. **약 11배 비용으로 +29.8%p**, 그리고 곡선이 눈에 띄게 오목하다(수확 체감).
- **Anthropic Opus 4.5 발표**: 중간 강도에서 이전 모델의 최고 점수를 **출력 토큰 76% 적게** 내고 같은 점수. 최고 강도에서는 **48% 적은 토큰으로 4.3%p 더**.

**결론: 강도는 켜고 끄는 스위치가 아니라 스윕해야 하는 다이얼이다.** 그리고 그 스윕 곡선 자체가 우리 시각화의 한 화면이 된다 (`--thinking-budget` 0 / 32 / 128 / 512).
