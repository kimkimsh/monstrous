# 주제 4. 가지 않은 길 — 반사실 재생기 (Counterfactual Replay)

> **한 줄 요약**
> 실행을 한 번 녹화해 두면, 그 다음부터는 **모델을 한 번도 더 돌리지 않고** 스쿼드 정책을 바꿔볼 수 있다. 심사위원이 슬라이더를 끌면 "포기 시점을 2턴 앞당겼다면 정확도 −1.2%p, 토큰 −38%"가 즉시 계산된다.

---

## 1. 문제 지문이 실제로 물은 것

> "You will design the squad entirely on your own, deciding which agents read the code, which ones modify it, which ones verify the results, and **which ones determine when it is time to give up**."

앞의 세 개는 모든 팀이 답할 것이다. 마지막 하나는 **답하기 어렵다.** 왜냐하면 "언제 포기하는 게 옳은가"는 실제로 포기해 보기 전에는 알 수 없고, 실제로 해보려면 매번 전체 실행을 다시 돌려야 하며, 그 실행은 돈이다.

이 주제는 그 고리를 끊는다. **한 번 비싸게 녹화하고, 그 뒤로는 공짜로 무한히 되돌린다.**

---

## 2. 어떻게 작동하는가

### 녹화 — 버려진 가지까지 남긴다

보통 트레이스는 "실제로 일어난 일"만 기록한다. 우리는 **일어날 수 있었던 일**도 기록한다.

```
문항 coding-visible-0007
├─ 시도 1  Editor  →  patch A  (preflight 실패)   [토큰 1,240]
├─ 시도 2  Editor  →  patch B  (preflight 통과)   [토큰 1,180]   ← 실제 제출
└─ 시도 3  (예산 있었으면 갔을 자리)               [미실행]

각 시도에 붙는 것: 그 시점의 누적 토큰, 자기보고 확신도,
                   결정론적 검사 결과, 그리고 **그 시도만 제출했을 때의 채점 결과**
```

핵심은 마지막 줄이다. **각 중간 시도를 로컬 채점기에 한 번씩 돌려서 점수를 미리 붙여 둔다.** LiveCodeBench는 공개 테스트 케이스로 로컬 실행이 가능하고, math는 `math_verify`, generic은 `letter_match`로 즉시 채점된다. 이게 있으면 "n번째 시도에서 멈췄다면 몇 점이었나"가 **재실행 없이 조회**가 된다.

### 재생 — 정책을 바꿔 끼운다

녹화 파일 위에서 다음을 자유롭게 바꿀 수 있다.

| 바꿀 수 있는 것 | 즉시 계산되는 것 |
|---|---|
| 최대 시도 횟수 (1, 2, 3, …) | 정확도, 총 토큰 |
| 확신도 문턱 | 계단을 올라간 문항 수, 비용 |
| 에이전트 한 명 제거 | 그 에이전트가 없었을 때의 결과 (ablation) |
| 트랙별 예산 재배분 | 가중합 총점 |
| `max_tokens` 상한 | `extraction_failed` 발생 수 |

모두 **LLM 호출 0회**다. 토큰 효율 30점을 지키면서 정책을 최적화하는 유일한 방법이다.

---

## 3. 왜 1등감인가

### 시각화 30점 — 채점 6축 중 가장 어려운 축을 정면으로 가진다

채점 기준의 여섯 축 중 다섯(observability, interpretability, traceability, explainability, clarity)은 잘 만든 트레이스 뷰어면 채워진다. 남는 하나가 **insightfulness — 보고 나서 몰랐던 것을 알게 되는가**이고, 여기가 사실상 승부처다.

반사실 재생기는 insightfulness를 직접 생산하는 장치다.

> **심사위원이 슬라이더를 직접 끌어서 자기 손으로 발견하게 만든다.** 우리가 결론을 말하는 게 아니라, 화면이 결론을 만들어 낸다.

기존 도구들과의 차이도 분명하다. Langfuse·LangSmith·Arize Phoenix·Honeycomb·OpenSearch Agent Traces — 전부 **일어난 일**을 보여준다. 학계 쪽 대표작인 AgentLens(IEEE TVCG 2025)도 계층적 요약과 원인 추적(cause trace)까지는 가지만, **정책을 바꿔 다시 돌려보는 기능은 없다.** "일어나지 않은 일"을 조회 가능한 데이터로 만든 에이전트 관측 도구는 아직 표준 제품에 없다.

### 토큰 효율 30점 — 튜닝 비용이 0이 된다

- 제출 실행 = 전액 과금, 테스트 실행 = 1/5 과금. **재생은 0이다.**
- 제출 슬롯은 대기 3개 / 동시 1개로 희소하다. 재생으로 정책을 확정하고 **제출은 최소 횟수만** 한다.
- 실험 계획(E1~E7 단일 변수 스윕)을 실제 실행이 아니라 재생으로 돌릴 수 있는 항목이 상당수다.

### 벤치마크 40점

같은 녹화 위에서 수백 가지 정책 조합을 훑어 **가중합 총점(0.5·coding + 0.25·math + 0.25·generic)을 최대화하는 설정**을 고른다. 감이 아니라 탐색이다.

## 4. 데모에서 보여줄 장면

한 화면에 세 개를 놓는다.

```
┌──────────────────────────────────────────────────────────┐
│  최대 시도    [1]──●──[2]───[3]───[4]                     │
│  확신도 문턱  [0.0]─────●────────[1.0]                    │
├──────────────────────────────────────────────────────────┤
│  총점  0.612  →  0.598   (−0.014)                        │
│  토큰  4.21M  →  2.61M   (−38%)                          │
│  파산  14건   →  47건                                     │
├──────────────────────────────────────────────────────────┤
│  [정확도 × 비용 산점도 — 슬라이더에 맞춰 점들이 색을 바꾼다] │
└──────────────────────────────────────────────────────────┘
```

슬라이더를 끄는 순간 숫자 세 줄이 동시에 움직인다. **"포기 판단"이라는 추상적 질문이 손에 잡히는 물건이 된다.**

## 5. 리스크와 솔직한 한계

| 리스크 | 내용 | 대응 |
|---|---|---|
| **가장 큰 한계: 반사실은 완전하지 않다** | 시도 2가 시도 1의 실패를 보고 쓰였다면, 시도 1을 제거한 세계에서 시도 2가 그대로 나온다는 보장이 없다 | **정직하게 화면에 적을 것.** "이 재생은 실행된 가지에 한해 정확하고, 제거된 가지 이후는 추정이다." 한계를 표시한 화면이 표시 안 한 화면보다 심사에서 낫다 |
| 녹화가 무거워진다 | 중간 시도까지 전부 채점하면 로컬 계산이 늘어난다 | LLM 비용은 0이다. CPU 시간만 든다. SWE-bench 로컬 채점은 Docker가 필요하므로 여기만 예외 처리 |
| SWE-bench 로컬 채점이 어렵다 | Docker 안에서 test_patch 적용 후 pytest | LiveCodeBench(로컬 실행 가능)를 코딩 능력 대리 지표로 쓰고, SWE-bench는 **패치 적용 가능성**을 대리 점수로 |
| 시각화를 나중에 붙이려 하면 전멸 | 로그를 안 남긴 실행은 되살릴 수 없다 | **러너를 만드는 첫 시간에 로거부터 심는다.** 반드시 `flush()` — 캡에 걸려 죽은 실행이 가장 흥미로운 자료다 |

## 6. 확인해야 할 것

- Trace 로그를 **어느 경로로 확보하는가.** 포털 `/api/teams/me/runs/{run_id}/details`의 `breakdown`은 `(agent_id, task_id, wave_index, model_id, calls, input_tokens, output_tokens)` 7개 필드뿐이고 **시간 필드가 없으며 문항 단위로 쪼개지지 않는다** (hidden 실행 보호 목적). 문항 단위 트레이스는 **우리가 로컬에서 만들어야 한다.**
- AI:GO 워크스페이스의 `logs/`, `plans/`, `tasks/` 디렉터리에 무엇이 실제로 떨어지는지 눈으로 확인.
- 녹화 스키마는 OpenTelemetry GenAI 표준 속성 위에 얹을 것 (`gen_ai.conversation.id`, `gen_ai.agent.name`, `gen_ai.operation.name`, `gen_ai.usage.cache_read.input_tokens`). 주최 측 열거형(`Outcome`, `FailureKind`, `FailureOwner`)을 그대로 쓰면 심사위원의 학습 비용이 0이다.
