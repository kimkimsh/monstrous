# 주제 3: Index-Localized Squad & Diff-Flow Explainability Engine
> **"Coding 트랙(가중치 0.5) 저격 무손실 문맥 인덱싱 및 OTel 4단계 줌 인과 추적 엔진"**

---

## 1. 한 줄 요약
**60,000자 저장소 문맥을 텍스트 요약(손실 발생) 대신 구조화된 위치 인덱스(`[path, line_range]`)로 정밀 타겟팅하여 무결점 Unified Diff를 생성하는 코딩 특화 스쿼드**와, **OpenTelemetry GenAI v1.41 표준 기반의 4단계 드릴다운 인과 추적 시각화 엔진**.

---

## 2. 기획 배경 및 문제의식 (Why)

1. **Coding 트랙이 전체 점수의 50%를 지배**:
   - 트랙 가중치 공식: $\text{Score} = 0.5 \times \text{Coding} + 0.25 \times \text{Generic} + 0.25 \times \text{Math}$
   - 문항 수는 generic이 많지만, 실제 순위를 가르는 결정적 승부처는 코딩(SWE-bench Lite + LiveCodeBench)입니다.
2. **요약(Summarization)의 치명적 함정 극복**:
   - 기존 에이전트들은 긴 코드를 요약하려다 함수 시그니처, 엣지 케이스, 변수명을 유실하여 패치 적용(fail-to-pass)에 실패합니다.
   - 주최 측 컨텍스트 번들은 이미 `{path, start_line, end_line, text}`로 정밀 구조화되어 있으므로, **"위치 인덱스"**만 추출하여 원본을 무손실 참조하는 것이 정답률과 토큰 효율 모두를 잡는 핵심입니다.
3. **시각화 채점 6대 축(추적성·설명성) 완전 공략**:
   - 심사 기준의 Traceability(추적성)와 Explainability(설명성)는 "최종 diff의 특정 변경 라인이 어떤 문맥 발췌에서 비롯되었는가"를 끊김 없이 연결할 때 만점이 부여됩니다.

---

## 3. 스쿼드 아키텍처 (How - Squad Architecture)

### 📌 무손실 인덱싱 & 패치 생성 파이프라인

```
┌─────────────────────────────────────────────────────────────────┐
│ 1. Context Bundles (60,000자 / 구조화된 코드 발췌 슬라이스)     │
└────────────────┬────────────────────────────────────────────────┘
                 │
                 ▼
┌─────────────────────────────────────────────────────────────────┐
│ 2. CodeReader (위치 특정)                                       │
│    출력: [Index #3 (django/db/models/query.py: L120-L145)]      │ ──▶ 요약 없이 인덱스만 50토큰 출력
└────────────────┬────────────────────────────────────────────────┘
                 │
                 ▼
┌─────────────────────────────────────────────────────────────────┐
│ 3. PatchWriter (정밀 패치)                                      │
│    출력: Strict Unified Diff (--- a/... +++ b/...)             │ ──▶ 인덱스 영역만 타겟 수정
└────────────────┬────────────────────────────────────────────────┘
                 │
                 ▼
┌─────────────────────────────────────────────────────────────────┐
│ 4. Verifier (문법 및 헝크 검증)                                 │
│    출력: Validated Patch or Targeted Feedback                  │ ──▶ docker 적용 오류 사전에 차단
└─────────────────────────────────────────────────────────────────┘
```

### 👥 에이전트 역할 구성
- **CodeReader**: 대규모 소스 발췌본을 스캔하여 결함 발생 지점의 파일명과 라인 인덱스 배열(`[3, 7]`)만 초소형으로 출력
- **PatchWriter**: 지정된 인덱스 블록만을 입력받아 PEP 8 및 프로젝트 컨벤션에 맞는 엄격한 Unified Diff 코드 생성
- **Verifier**: Diff 헤더 포맷(`--- a/`, `+++ b/`), 헝크 오프셋, 파이썬 AST 문법 적합성을 판정하여 `swebench_docker` 채점기 통과율 극대화

## 4. 인터랙티브 트레이스 시각화 (Trace Visualization)

### 🖥️ `Diff-Flow Explainability Engine` 핵심 화면
1. **OTel 표준 4단계 Zoom-in 네비게이션**:
   - **Level 1 (Overview)**: 364개 벤치마크 문항의 성공/실패/토큰 맵
   - **Level 2 (Wave Swimlane)**: 에이전트 간 핸드오프 및 타임라인 워터폴
   - **Level 3 (Span Graph)**: OTel GenAI v1.41 규격의 부모-자식 인과 트리
   - **Level 4 (Interactive Diff Inspector)**: 컨텍스트 발췌 위치 $\leftrightarrow$ 최종 코드 Diff 간 라인 매핑 및 설명 툴팁
2. **Span-to-Patch Lineage View**:
   - 최종 생성된 코드 diff의 각 줄을 클릭하면 해당 코드를 생성한 프롬프트 지시와 CodeReader의 인덱스 추론 근거로 즉시 하이라이트 이동.
