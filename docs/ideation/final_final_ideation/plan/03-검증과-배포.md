# 부록 3 — 검증과 배포

`squad/squad_template/monstrous_squad/`의 산출물을 **어떤 순서로 검사하고, 어디에 넣고, 무엇을 확인하면 끝인지**를 적는다.

---

## 1. 폴더에 무엇이 있나

```
squad/squad_template/monstrous_squad/
├── squad-template.json          제출물. 다섯 systemPrompt가 사는 유일한 원본이다
├── squad-template.min.json      대비책. toolConfig 두 필드를 비운 판. 나머지는 동일
├── budget.json                  aigo squad budget set에 그대로 넣는 본문
├── README.md                    이 폴더 단독으로 읽을 수 있는 요약
└── tools/
    ├── make_min_template.py     squad-template.json에서 .min.json을 파생
    ├── validate_template.py     임포트 규칙 + 실제 채점기 + 두 판의 동기화 검사
    └── make_update_body.py      템플릿이 못 싣는 maxTokens·maxToolCalls를 넣는 update 본문 생성
```

**`squad-template.json`을 직접 고친다. 그것이 원본이다.** `docs/.../spec/squad-template.json`에 있던 설계 사본은 삭제했다 — 같은 프롬프트가 두 파일에 살면 어느 쪽이 제출물인지가 매번 다시 물음이 되기 때문이다. 고친 뒤에는 `tools/make_min_template.py`를 돌려 `.min.json`을 다시 파생하고, `validate_template.py`가 두 판이 `disabledTools`·`toolPermissionOverrides` 말고 다른 데서 어긋나지 않았는지 검사한다.

## 2. 로컬 검사 — LLM 호출 0회

```bash
cd /Users/mark-mac/workspace/monstrous

# 1. squad-template.json을 고쳤다면 .min.json을 다시 파생한다
python3 squad/squad_template/monstrous_squad/tools/make_min_template.py

# 2. 임포트 규칙 + 채점기 규칙 검사
python3 squad/squad_template/monstrous_squad/tools/validate_template.py \
        squad/squad_template/monstrous_squad/squad-template.json
python3 squad/squad_template/monstrous_squad/tools/validate_template.py \
        squad/squad_template/monstrous_squad/squad-template.min.json
```

`validate_template.py`가 실제로 보는 것은 다음과 같다. 전부 바이너리 문자열이나 `grade.py` 함수에 대응하며, 문서만 근거로 삼은 검사는 하나도 없다.

| 묶음 | 검사 |
|---|---|
| **임포트 한도** | `id` ≤200자·제한 문자셋, `name` ≤200, `description` ≤5,000, 에이전트 ≤50, `systemPrompt` ≤50,000/명, 도구 목록 ≤100 |
| **열거형** | `category` ∈ {development, content, research, review, custom}, `isBuiltin` = false |
| **구조** | `planner` role이 정확히 1명, 에이전트 키가 9개 스키마 안에 있는지(밖이면 조용히 버려지므로 경고) |
| **도구** | `tools`와 `toolConfig.enabledTools`가 **둘 다 비어 있는지**. 이것 하나가 실제로 도구를 0개로 만드는 손잡이라 검사기가 값이 들어오면 실패한다 |
| **모델** | `preferredModelId`가 `providers.json`이 실제로 서빙하는 셋 중 하나인지 |
| **채우면 안 되는 것** | `minContextWindow`가 `null`인지, `requiresToolCalling`/`requiresVision`/`memoryEnabled`가 `false`인지 — 각각 실패 시 이유를 그 자리에서 출력한다 |
| **프리픽스 캐시** | 다섯 `systemPrompt`의 Layer 1이 **바이트 단위로 같은지** (`sha256`), 그리고 캐시 최소 문턱을 넘길 길이인지 |
| **채점기** | Layer 1 안 worked example 6개를 `grade.py`의 `extract_boxed` / `extract_letter` / `extract_patch` + `parse_edit_blocks`에 **실제로 먹여**, `Correct` 라벨은 파싱되고 `Wrong` 라벨은 안 되는지 |
| **ledger** | 프롬프트에 적힌 ledger 예시가 한 줄인지, 그 자체로 답으로 추출되지 않는지, `**Execution`으로 시작하지 않는지 |
| **예산** | 옆의 `budget.json`이 `BudgetConfig` 11개 키와 정확히 일치하는지, 값이 전부 정수인지, `task ≤ agent ≤ total` 제약과 `warning_threshold_percent ∈ [0,100]`을 지키는지, `maxTasksPerPlan`이 플랜 A(3태스크)를 표현할 수 있는지 |

현재 통과 상태:

```
squad-template.json: 5 agents, 83714 bytes
  note  Architect: role 'Architect' maps to custom (whole-string match, no substrings)
  note  Solver: role 'Solver' maps to custom (whole-string match, no substrings)
  note  Layer 1 identical across 5 agents, 10292 chars, sha256 c5fec0a204c33189
  note  budget.json: 120000 total, 3 tasks/plan, 4 turns, concurrency 1
all checks passed
```

## 3. 앱에 넣기

### 3-1. 순서

```bash
# 1. 템플릿 가져오기
aigo squad template import squad/squad_template/monstrous_squad/squad-template.json
aigo squad template list          # 목록에 보이는지

# 2. 이 템플릿으로 스쿼드 만들기 (workspacePath는 절대 경로)

                    "workspacePath":"/Users/mark-mac/workspace/monstrous/squad/monstrous",
                    "templateId":"user-monstrous-squad-v1"}'

# 3. 템플릿이 못 싣는 것을 넣는다 — 출력 상한과 도구 라운드 수
#    .min.json 으로 임포트했다면 그 파일을 두 번째 인자로 준다. 안 그러면 임포트가
#    거부한 22+22를 update 가 다시 밀어 넣는다

# 5. 설정이 실제로 들어갔는지 파일로 확인한다 (UI로는 확인 안 된다, §3-3)

  | grep -E 'preferredModelId|enabledTools|memoryEnabled|maxTokens|maxToolCalls'

# 6. 한 문항 돌려 보기

  "$(cat docs/resource/example_task/coding/requests/coding-visible-0001.txt)"

# 7. 답이 나왔는지 — 이것만이 중요한 확인이다
python3 docs/resource/example_task/tools/extract.py <워크스페이스>
```

### 3-2. 세 개의 JSON이 서로 다른 명령으로 들어간다

| 무엇 | 어느 명령 | 받는 타입 |
|---|---|---|
| 프롬프트·모델·도구·메모리·role·icon | `aigo squad template import` → `create` | `SquadTemplate` (최상위 12키, 에이전트 9키) |
| **`maxTokens`(출력 상한)·`maxToolCalls`(도구 라운드)** | **`aigo squad update`** | **`UpdateSquadRequest`** → 에이전트가 `AgentConfig`(14키)라 `settingsOverrides`가 실린다 |
| 예산 11개 키 | `aigo squad budget set` | `BudgetConfig` |

값과 근거는 `01-JSON-필드-결정표.md` §6-2. 요약하면 `maxTokens` 8192(전원), `maxToolCalls` Router 8 / 나머지 0, 나머지 넷은 `null`.

**UI로 넣어야 하는 것은 이제 하나뿐이다** — 전역 `inference.defaultReasoningEffort`. 스쿼드도 에이전트도 아닌 앱 설정이라 어느 JSON에도 자리가 없다. 현재 값은 `none`이고, 첫 실행 전에 확인한다.

### 3-3. 임포트 후 UI에서 도구가 안 골라진다 — 정상이다

`enabledTools: []`가 도구를 0개로 만드는 것이 설계이므로, 화면에 고를 것이 없는 상태가 우리가 원하는 상태다. **다만 그래서 "템플릿이 제대로 들어갔는가"를 UI로는 확인할 수 없다.** 위 5번처럼 파일로 확인한다. 화면이 잠긴 원인 후보 셋과 각각의 30초 확인법은 `01-JSON-필드-결정표.md` §1-4-1에 있다.

### 3-4. 걸림돌 셋 — 미리 안다

- **지금 이 PC에서는 CLI가 앱에 닿지 않는다.** 데스크톱 앱은 떠 있는데(`backend-ai-go` PID 확인) 관리 API 포트가 안 열려 있다.

  ```
  $ aigo squad list
  Error: Failed to connect to http://127.0.0.1:8001: error sending request for url (…/api/v1/squads)
  ```

  **[디스크]** `settings.json`은 `managementApi.enabled = true`, `port = 8001`, `bindHost = 127.0.0.1`, `authEnabled = false`인데 리스너가 없고, 발견 파일 `mgmt-api.json`도 사라져 있다. **위 §3-1의 3·4번(`aigo squad update`, `budget set`)이 이 상태에서는 실행되지 않는다.** 트레이 메뉴의 TCP API 서버를 켜거나 앱을 재시작해서 8001이 열리는지 먼저 확인한다.

  **그리고 열려도 끝이 아니다** — 헤드리스 서버의 OpenAPI에는 경로 243개 중 **스쿼드 엔드포인트가 0개**였다. 데스크톱 앱의 관리 API가 `/api/v1/squads`를 실제로 서빙하는지는 열어 봐야 안다. 안 서빙하면 남는 통로는 앱 UI뿐이고, 그러면 `maxTokens`·`maxToolCalls`를 손으로 넣어야 한다.
- **1.12.1 헤드리스에서는 Planner가 돌지 않는다.** 실행을 접수하고 빈 플랜을 쓴 뒤 `taskCounts.total = 0`으로 멈춘다. **반드시 데스크톱 앱을 띄운 상태에서 검증한다.**
- **로그는 덮어써진다.** `squad/test`는 이벤트 id 0~50과 44,333토큰짜리 실행 하나를 통째로 잃었고, `logs.zip` 안에만 남아 있다. **실행마다 `viz/tools/snapshot-logs.sh`로 워크스페이스를 스냅샷한다.** 시각화 30점의 입력이 그것뿐이다.

## 5. `check`가 무료라는 사실이 이 표에서 가장 중요하다

같은 토큰이라도 submission run은 test run의 5배로 계산된다(계수 1.0 대 0.2). 그런데 **일감 크기가 다르다.**

| | 토큰 | 계수 | 실효 |
|---|---|---|---|
| 연습 세트 121문항 한 바퀴 | 약 5.5~7.7M | 0.2 | 약 1.1~1.6M |
| hidden 제출 1회 (**147문항 실측**) | 약 7.1M | 1.0 | 7.1M |

**[2026-08-23] hidden 세트가 147문항으로 실측되면서 이 비교가 뒤집혔다.** 연습이 121, hidden이 147로 거의 같다. **제출 1회 ≈ 연습 전량 스윕 약 5회분**이다 — 초안의 "약 26~32회분"은 hidden을 889문항으로 잡은 값이었다. 확신 없이 submit 하지 않는다. 대기 큐는 최대 3건, 동시 실행 1건이고 `check`만 무료·무제한이다.
