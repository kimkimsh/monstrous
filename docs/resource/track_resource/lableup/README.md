1. **제출 포털에 로그인해서 `/submit` 페이지를 연다.** 제출 JSON의 정확한 필드 구조는 로그인 뒤에만 보이며, 이걸 모르면 아무것도 못 낸다. Development key도 여기서 발급받는다.

3. **트레이스 로거부터 심는다.** 시각화 30점의 입력이다. 나중에 붙이려 하면 이미 돌린 실행은 되살릴 수 없다. 스키마는 [06번 문서 4절](06-시각화-설계-가이드.md).

## 이 자료에서 가장 값나가는 발견 다섯

PDF만 읽어서는 절대 알 수 없고, 다른 팀도 대부분 모를 것들이다.

1. **coding 트랙 가중치가 0.5다.** 문항 수는 generic이 2~5배 많은데 점수의 절반은 coding이 가져간다.
2. **평가 실행 중 스쿼드는 도구가 없다.** 저장소 코드는 judge가 검색해서 **문항당 60,000자로 잘라** 요청에 넣어준다. 검색·탐색 에이전트를 설계하는 것은 헛수고다.
3. **평가 모델 3개 중 2개가 reasoning 모델이고, 하나는 출력 예산의 97%를 사고 토큰에 쓴다.** 토큰 캡이 reasoning 스쿼드에 약 10배 세게 물린다.
4. **prefix cache가 비용을 좌우한다.** 포털이 직접 "긴 안정 프리픽스를 변하는 부분 앞에 두면 진짜 여유가 생긴다"고 안내한다. `cached_input_share`가 API로 노출되므로 측정 가능하다.
5. **연습 세트 364문항이 통째로 공개되어 있다.** 실제 채점 세트와 같은 형식·구성 규칙·채점기를 쓴다. 이걸 안 쓰고 감으로 튜닝하는 팀과는 출발선이 다르다.
