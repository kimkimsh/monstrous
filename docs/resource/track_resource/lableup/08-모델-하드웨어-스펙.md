# 08. 모델 · 하드웨어 스펙

> 이 트랙에서 실제로 쓰이는 모델과, 트랙 공동 주최사 FuriosaAI의 하드웨어 정보를 정리한다.
> 트랙의 배경 질문이 *"How far can you go with a model you can actually hold in your hands?"* 이므로, **모델이 왜 이 크기인지**를 아는 것이 피칭에도 도움이 된다.

---

> **[갱신됨 2026-08-22]** 아래 내용은 2026-08-21 조사 시점 기준이며 이후 실측으로 뒤집혔다. 최신 사실은 `docs/ideation/final_final_ideation/spec/`를 따른다. 평가 모델 3종은 이후 `providers.json`에서 `furiosa-ai/Qwen3-32B-FP8`(×1) · `furiosa-ai/gpt-oss-120b`(×2) · `furiosa-ai/K-EXAONE-236B-A23B-NVFP4A16`(×3)로 확인됐다. 아래 `Qwen3-30B-A3B-Instruct-2507-FP8` 관련 수치는 그 이전 추정이다.

## 1. 확인된 평가 모델

포털의 Development usage 화면(PDF 21페이지 스크린샷)에서 **실제로 관측된** 모델은 하나다.

```
Qwen3-30B-A3B-Instruct-2507-FP8
```

리더보드 안내문에 따르면 **평가 모델은 총 3개이고, 그중 2개가 reasoning 모델**이다. 위 모델은 이름에 `Instruct`가 붙어 있고 Qwen 공식 문서상 non-thinking 모델이므로, **3개 중 유일한 instruct 모델**로 보는 것이 합리적이다.

나머지 2개는 온보딩 세션이나 포털 로그인 후 확인해야 한다. Qwen3 계열이라면 `Qwen3-30B-A3B-Thinking-2507`이 유력한 후보이나 **추측이므로 확인 전까지 신뢰하지 말 것.**

## 2. Qwen3-30B-A3B-Instruct-2507

Alibaba(Qwen 팀)의 2025년 7월 릴리스. Qwen3-30B-A3B의 instruct 갱신판이며, thinking 체크포인트와는 **별개의 모델**이다.

### 아키텍처

| 항목 | 값 |
|---|---|
| 타입 | Causal Language Model (`Qwen3MoeForCausalLM`) |
| 구조 | **MoE (Mixture-of-Experts, 전문가 혼합)** — 여러 개의 전문가 신경망 중 일부만 골라 쓰는 구조 |
| 총 파라미터 | **30.5B** (정확히 30,532,122,624개) |
| **활성 파라미터** | **3.3B** — 토큰 하나를 처리할 때 실제로 계산에 참여하는 양 |
| 비임베딩 파라미터 | 29.9B |
| 레이어 수 | 48 |
| 어텐션 헤드 (GQA) | Q 32개 / KV 4개 |
| 전문가 수 | **128개** |
| 활성 전문가 수 | **8개** |
| 컨텍스트 길이 | **262,144 토큰** (네이티브) |
| 최대 출력 | 32,000 토큰 |
| 사고 모드 | **없음 (non-thinking)** — `<think>` 블록을 내지 않는다 |

> **MoE가 이 트랙에서 왜 중요한가** — 30.5B 모델이지만 토큰당 3.3B만 계산한다. 즉 **메모리는 30B급을 요구하지만 연산량은 3B급**이다. 이것이 "손에 쥘 수 있는 모델"의 실체다. 노트북 GPU나 NPU 한 장에 올라가면서 훨씬 큰 모델에 가까운 성능을 낸다.

### FP8이 붙은 이유

`-FP8` 접미사는 **가중치를 8비트 부동소수점으로 양자화**했다는 뜻이다. BF16 대비 메모리가 절반이고, FP8 연산 유닛이 있는 하드웨어에서는 처리량이 2배가 된다.

FuriosaAI RNGD의 스펙(4절)을 보면 BF16 256 TFLOPS / **FP8 512 TFLOPS**다. **FP8 체크포인트를 쓰는 이유가 하드웨어와 정확히 맞물린다.**

## 3. reasoning 모델에 대해 알려진 것

직접 이름을 확인하지 못했으나, 리더보드가 알려준 특성은 명확하다.

> Two of the three evaluation models are reasoning models — **one was measured spending 97% of its output budget on reasoning tokens before it answered** — so a token cap bites roughly **an order of magnitude harder** on a squad built from reasoning models than on one built from an instruct model.

- 출력 예산의 **97%가 추론 토큰**. 답 자체는 3%.
- 토큰 캡이 **약 10배** 세게 물린다.

Qwen3 계열의 하이브리드 사고 모델이라면 AI:GO의 다음 스위치로 제어 가능하다 (`03-AIGO-Squad-완전가이드.md` 13절):
- `--no-think` → `chat_template_kwargs: {"enable_thinking": false}`
- `--reasoning-effort none|low|medium|high|xhigh`
- `--thinking-budget N` → `thinking_budget_tokens: N` (`-1` 무제한, `0` 즉시 종료, `N>0` 하드 캡)
- `--preserve-thinking` → 이전 턴의 `<think>` 블록 유지 (Qwen3.6+, KV 캐시 재사용 개선)

**`--thinking-budget`이 엔진 무관하게 동작한다는 점이 중요하다.** llama-server와 mlxcel-server 양쪽에서 작동하며 continuum-router 패스스루로도 전달된다. **reasoning 모델을 쓰되 비용을 예측 가능하게 만드는 유일한 레버다.**

## 4. FuriosaAI RNGD ("Renegade")

트랙 공동 주최사 FuriosaAI의 2세대 NPU. 21:30 온보딩 세션의 주제이기도 하다.

### 왜 알아야 하나

트랙의 배경 질문 *"내 손에 쥘 수 있는 모델로 어디까지"* 는 **"빅테크 GPU 인프라 없이도 된다"** 는 주장이다. RNGD는 그 주장의 하드웨어 쪽 근거다. 우리 스쿼드가 30B급 MoE 모델 하나로 프론티어 모델급 결과를 낸다면, 그것이 곧 이 하드웨어가 팔릴 이유가 된다. **피칭에서 이 연결을 짚으면 트랙 파트너에게 정확히 꽂힌다.**

### 사양

| 항목 | 값 |
|---|---|
| 아키텍처 | **Tensor Contraction Processor (TCP)** — 텐서 축약 연산을 하드웨어에서 직접 실행하는 구조 |
| 공정 | TSMC 5nm |
| 클럭 | 1.0 GHz |
| BF16 | **256 TFLOPS** |
| **FP8** | **512 TFLOPS** |
| INT8 | 512 TOPS |
| INT4 | 1,024 TOPS |
| 메모리 | **HBM3 48 GB** (모듈 2개) |
| 메모리 대역폭 | **1.5 TB/s** |
| 온칩 SRAM | **256 MB** |
| 인터커넥트 | PCIe Gen5 x16 |
| 냉각 | 패시브 |
| **TDP** | **150 W** (개발자 문서) / **180 W** (2025.3.0 데이터시트) ※ 자료 간 불일치 |
| 전원 커넥터 | 12VHPWR |
| 폼팩터 | PCIe 듀얼 슬롯, 풀 하이트, 3/4 길이 |
| Multi-Instance | 8 |
| 가상화 | 지원 (SR-IOV, 가상 함수 8개) |
| ECC 메모리 | 지원 |
| Secure Boot | Root of Trust 포함 |

> TDP 수치가 자료마다 다르다. 개발자 문서(`developer.furiosa.ai`)는 150W, 2025.3.0 데이터시트 PDF는 180W로 적는다. 인용할 때는 출처를 함께 밝힐 것.

### 배포 특성

- 공랭 4U 서버 하나에 **최대 8장**까지 장착
- 온프렘, 엔터프라이즈 데이터센터, 소버린 AI 클라우드 모두 대상
- PyTorch 2.x 통합. FuriosaSDK 제공
- BF16 / FP8 / INT8 / INT4 지원

### FP8과의 연결

RNGD는 **BF16 256 TFLOPS 대비 FP8이 512 TFLOPS로 정확히 2배**다. 그리고 이번 트랙의 확인된 모델이 `Qwen3-30B-A3B-Instruct-2507-**FP8**`이다.

여기에 **활성 파라미터 3.3B**를 곱하면 그림이 완성된다. 30.5B 가중치를 FP8로 담으면 약 30GB — **HBM3 48GB에 여유 있게 들어간다.** 그리고 토큰당 연산은 3.3B 상당이라 1.5TB/s 대역폭으로 충분히 먹인다.

**즉 이 모델과 이 하드웨어는 서로를 위해 고른 조합이다.** 트랙 문제 설정이 우연이 아니다.

## 6. 요약 — 이 정보를 어떻게 쓰나

1. **generic 트랙(MMLU-Pro)에서 단일 모델 기준선이 78.4다.** 스쿼드로 이걸 크게 넘기는 어렵다. **여기에 토큰을 붓지 말 것.**
2. **coding 트랙(LiveCodeBench v6)에서 기준선이 43.2, Aider-Polyglot은 35.6으로 약점이다.** 가중치도 0.5다. **스쿼드 설계의 부가가치가 가장 큰 곳.**
3. **math 트랙(AIME25)에서 61.3이다.** non-thinking 모델치고 매우 높다. thinking 모델로 바꿔서 얻는 이득이 그 비용을 정당화하는지 반드시 실측할 것.
4. **컨텍스트 길이는 병목이 아니다.** 17k 토큰 구간에서 RULER 97%대. 요약 압축보다 원본 + 캐시 전략이 유리할 가능성이 높다.
5. **피칭 재료**: "FP8 30B MoE 하나 + 잘 짜인 스쿼드로 프론티어 모델급 결과" 는 Lablup의 `intelligence like electricity`와 FuriosaAI의 `180W로 데이터센터 추론` 양쪽 서사에 정확히 들어맞는다.
