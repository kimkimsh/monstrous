# monstrous 트레이스 뷰어 — 사용 설명서

AI:GO 스쿼드가 남긴 로그를 읽어서 **"이 실행이 점수가 되는가, 안 된다면 누가 고쳐야 하는가"**
를 화면으로 보여주는 도구입니다.

HTML 파일 하나입니다. 더블클릭하면 열립니다. 설치도, 서버도, 인터넷 연결도 필요 없습니다.

## 1. 1분 만에 시작하기

### 1-1. 파일 열기

```
viz_revise_program/trace-visualizer.html
```

이 파일을 더블클릭하면 브라우저가 뜹니다. Chrome 또는 Safari를 권합니다.

> **`src/app.html` 이 아니라 `trace-visualizer.html` 을 엽니다.**
> `src/app.html` 이 원본, `trace-visualizer.html` 이 빌드 결과입니다. 둘의 내용은 같지만, 원본을 고친 뒤에는
> 반드시 빌드를 다시 돌려야 산출물에 반영됩니다 ([14-5](#14-5-화면이-옛날-그대로입니다) 참고).

### 1-2. 폴더 넣기

첫 화면에 **코인 투입구** 모양의 상자가 있습니다. 여기에 워크스페이스 폴더를
**끌어다 놓거나**, 아래 `워크스페이스 폴더 고르기` 버튼을 누릅니다.

**중요 — 어느 폴더를 골라야 하나요?**

`logs/` 폴더가 아니라 **그 상위 폴더**입니다.

```
squad/test/            ← 이것을 고릅니다
├── .squad.json
├── logs/              ← 이것을 고르면 안 됩니다
│   ├── history.json
│   ├── events.jsonl
│   └── <실행id>.jsonl
├── tasks/
└── artifacts/
```

여러 워크스페이스를 한 번에 보고 싶으면 **그 위 폴더**를 고릅니다.
예를 들어 `squad/` 를 고르면 그 안의 `test`, `test_2`, `ikkim` 이 전부 들어오고
「스쿼드 비교」 모드가 켜집니다.

### 1-3. 다 됐습니다

폴더를 놓으면 700ms 짜리 오프닝이 한 번 재생되고, 왼쪽에 실행 목록이 쌓입니다.
아무 실행이나 클릭하면 그 실행의 판정이 오른쪽에 섭니다.

## 2. 무엇을 읽고 무엇을 못 읽나

### 2-1. 읽는 파일

| 파일 | 필요한가 | 이 파일에만 있는 것 |
|---|---|---|
| `logs/history.json` | **필수** | 응답 본문, 에이전트 이름, 요청 원문 |
| `logs/events.jsonl` | **필수** | 웨이브 구조, 플래너 경고, 토큰 시계열, 실패 에러 |
| `logs/<실행id>.jsonl` | 선택 | 사람이 읽는 로그, **웨이브가 끝난 시각** |
| `.squad.json` | **강력 권장** | 스쿼드 구성·모델·도구·시스템 프롬프트 |
| `tasks/*.json` | 선택 | 의존 관계, 큐 대기 시간, 재시도 횟수, 우선순위 |
| `tasks/*.md` | 선택 | 시도 단위 기록 |
| `artifacts/*` | 선택 | 에이전트가 워크스페이스에 쓴 파일 |
| `artifacts/reports/*.md` | 선택 | AI:GO 자체 실행 요약 |
| `logs/index.json` | 참고만 | 실행의 스쿼드 id. **개수와 시각은 못 믿습니다** |

`history.json` 과 `events.jsonl` 중 하나만 있어도, 그릴 수 있는 것까지는 그립니다.
빠진 것이 있으면 화면이 무엇을 못 그렸는지 알려 줍니다.

### 2-2. 못 읽는 것 — 그래서 안 그리는 화면

이 도구는 **로그에 없는 값으로 화면을 만들지 않습니다.** 다음은 만들 수 없어서 안 만든 것들입니다.

| 그리고 싶지만 못 그리는 것 | 이유 |
|---|---|
| 캐시 히트율 | 캐시 필드가 로그에 없습니다. 제출 포털에만 있습니다 |
| 모델별 비용 | **모델 이름이 로그 어디에도 없습니다** |
| 태스크별 정확한 토큰 | `history.json` 의 태스크별 `tokenUsage` 가 전부 `{0, 0}` 입니다 |
| 에이전트별 정확한 토큰 | 같은 이유. 그래서 **추정치**로 내고 `(추정)` 을 붙입니다 |
| 도구 호출 트레이스 | `tool_use` 계열 키가 전 워크스페이스에 0건입니다 |

> **실행 하나의 총 토큰(`totalTokenUsage`)은 정확합니다.**
> 문항 하나 = 실행 하나이므로, 문항 단위 비용 분석에는 아무 문제가 없습니다.

### 2-3. 화면이 지키는 정직성 규칙 네 가지

1. **없는 값에는 카드를 세우지 않습니다.** 빈 카드에 "데이터 없음"을 띄우는 대신
   카드 자체가 나오지 않습니다.
2. **추정값에는 반드시 `(추정)` 을 붙이고**, 나눌 수 없는 몫은 나누지 않고
   "미귀속"으로 남깁니다.
3. **시계열을 보간하지 않습니다.** 누적 토큰은 보고된 시점에만 계단으로 오릅니다.
   사이를 이으면 로그에 없는 숫자를 화면이 지어내는 것이 됩니다.
4. **모르는 것을 불합격으로 적지 않습니다.** 「판정 보류」와 「채점 부적격」은
   다른 상태이고, 화면에서도 다른 색입니다.

## 4. 상단 계기판 읽는 법

계기가 넷입니다. 창이 좁아지면 계기가 **하나씩 통째로** 사라집니다. 숫자가 잘리는 일은
없습니다 — 사라진 것은 사라진 줄 알지만, 잘린 숫자는 다른 숫자로 읽히기 때문입니다.

사라지는 순서는 **TIME → 실행 → AI:GO ⇄ 채점 적격** 이고 **CREDITS 가 마지막까지 남습니다.**
환산 비율(`1칸 = 8.0k tok`)을 빼면 칸이 단위를 지어내는 셈이 되기 때문입니다.

| 창 폭 | 보이는 계기 |
|---|---|
| 1480px 이상 | 넷 다 |
| 1360 ~ 1480 | 실행 · ⇄ · CREDITS |
| 1260 ~ 1360 | ⇄ · CREDITS |
| 1260px 미만 | CREDITS |

경계값은 **영어 라벨 기준**입니다. `AI:GO success ⇄ Gradable` 이 한국어 라벨보다 넓어서,
한국어에 맞춰 잡으면 언어를 바꾸는 순간 숫자가 잘립니다.

### 4-1. 실행

로드된 실행의 총 개수입니다. 아래 작은 글씨에 읽은 파일 수와 스쿼드 수가 붙습니다.

### 4-2. AI:GO 성공 ⇄ 채점 적격

**이 계기 하나 보자고 만든 도구입니다.**

- 왼쪽 숫자 — AI:GO 가 "태스크가 다 끝났다"고 본 실행 수
- 오른쪽 숫자 — 실제로 **점수가 되는** 실행 수
- 아래 줄 — `두 판정이 갈린 N건`

두 숫자가 갈리는 건 보는 것이 다르기 때문입니다.

| | 보는 것 |
|---|---|
| AI:GO | 태스크가 끝났는가 |
| 제출 서버 | **응답에 요구된 답 형식이 있는가** |

점수가 되는 것은 뒤쪽입니다. 갈린 건수가 0이 되면 아래 줄이 `두 판정이 일치` 로 바뀌고
색이 초록이 됩니다.

### 4-3. CREDITS — 이 화면의 시그니처

```
CREDITS  154.6k  ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓░
                 1칸 = 8.0k tok
```

토큰을 **칸으로** 셉니다. 20칸입니다.

- **칸당 토큰은 고정값이 아닙니다.** `총 토큰 ÷ 20` 을 유효숫자 한 자리로 올려서 정합니다.
  데이터가 바뀌면 환산 비율도 같이 바뀝니다.
- **칸은 보조 표기입니다.** 실제 토큰 수를 항상 왼쪽에 같이 적습니다.
- 「전체 분석」의 절단선을 끌면 **이 계기가 실시간으로 줄어듭니다.**
  잘려나간 칸은 사라지지 않고 **빗금(디더)으로 남습니다** — 줄어든 값과 원래 값이
  동시에 보여야 실험이 실험으로 읽히기 때문입니다.

### 4-4. TIME

전체 wall-clock 합계입니다. 아래에 실행당 평균이 붙습니다.

## 6. 「실행 하나」 모드의 탭 여섯 개

### 6-0. 좌측 실행 목록

행 하나가 실행 하나입니다. 한 행에 네 가지가 있습니다.

```
┃ ∑ MATH   What is the maximum value o…     ← 계열색 막대 + 트랙 + 요청 앞 64자
  [채점 적격]  AI:GO 3/3                    ← 판정 도장 + AI:GO 카운트
  ▓▓▓▓▓▓▓░░░░░  8.1k tok · 118.1s           ← 토큰 셀 게이지 + 실제 값
```

- **왼쪽 세로 막대**의 색은 **스쿼드**를 뜻합니다 (판정이 아닙니다).
- **셀 게이지는 로그 눈금**입니다. 토큰이 1k에서 1M까지 세 자리수 넘게 벌어지기 때문에
  선형으로 나누면 행 대부분이 0칸이 되어 아무것도 못 알려 줍니다.
  **정확한 값은 항상 오른쪽 숫자에 있습니다.** 칸은 크기 감각을 주는 보조 표기입니다.
- 상단 필터로 「채점 적격만」·「답 형식 없어서 0점인 것」 같은 부분집합만 볼 수 있습니다.
- `▤` 버튼을 누르면 **격자 보기**로 바뀝니다. 전체 지형을 한눈에 볼 때 편합니다.
- 실행이 200건을 넘으면 200건씩 끊어 그리고 아래에 `더 보기` 가 붙습니다.
  `j` 로 목록 끝에 닿으면 자동으로 다음 쪽이 이어집니다.

### 6-1. 개요 — 이 실행이 무엇을 했고 점수가 되는가

화면이 **네 층**으로 나뉩니다. 위에서부터 중요합니다.

**① 결론 층** — 스크롤하지 않아도 항상 보입니다.

```
┌─────────┐
│ 채점 적격 │   Solve inequality 안에 있습니다        ∑ MATH
│  GRADED  │   AI:GO 판정 completed · 태스크 1/1 성공  FINAL ANSWER: \boxed{<answer>}
└─────────┘
              토큰   1.5k (in 528 · out 926)
              소요   136.8s
              웨이브  W1: 1
```

왼쪽의 **도장**이 판정입니다. 오른쪽 위에 **트랙**과 **그 문항이 요구한 출력 계약**이 붙습니다.

**② 경고 층** — 있을 때만 나옵니다. 순서가 고정돼 있습니다.

여기가 제일 손이 많이 간 자리입니다. 예를 들어:

> **답은 맞혔는데 보기 문자를 내지 않았습니다.**
> 응답의 `1680` 는 보기 `D. $1,680` 와 같은 값입니다. 채점기는 `letter_match` 라서
> 값이 아니라 문자 하나를 봅니다. `D` 한 글자만 냈으면 점수가 됐습니다.

**한 글자 때문에 0점이 된 자리**를 결론 바로 아래에 올립니다. 각주로 내리지 않습니다.

경고는 다섯 종류가 있습니다.

| 경고 | 뜻 |
|---|---|
| 보기 문자는 냈는데 `ANSWER:` 줄이 아닙니다 | 문자는 맞는데 줄 형태가 계약과 다릅니다 |
| 답은 맞혔는데 보기 문자를 내지 않았습니다 | 값은 맞고 형식만 틀렸습니다 |
| 이 트랙의 계약이 지문에 없습니다 | 러너가 계약 절을 빠뜨리고 보냈습니다 |
| 플래너 폴백이 걸렸습니다 | 요청이 분해되지 않아 **에이전트 수만큼 풀 컨텍스트 호출**이 발생했습니다 |
| 답이 파일에만 있습니다 | `artifacts/` 에는 답이 있는데 응답 텍스트에 없습니다. judge 는 파일을 읽지 않습니다 |

**③ 근거 층** — 스쿼드 구성 표, 시간 배분 막대, 태스크 표.

스쿼드 구성 표에는 역할별 **도트 아바타**가 붙습니다. 이 실행에서 일하지 않은 구성원은
흐리게 표시됩니다. 태스크 표의 **대기** 열이 10초를 넘으면 노란색이 됩니다.

**④ 각주 층** — 접혀 있습니다. 필요할 때만 펴십시오.

- AI:GO 자체 요약과 대조
- 워크스페이스에 쓴 파일
- 스쿼드 설정 (`minContextWindow` 미설정 경고가 여기 있습니다)

> **AI:GO 와 우리 판정이 갈리는 실행에서는 그 각주가 저절로 펴진 채로 나옵니다.**
> 여기서 얘기가 갈리니까 접어 두지 않습니다. 발표 모드에서도 이 각주만은 안 접힙니다.

### 6-2. ▶ 재생 — 시간과 토큰이 실제로 언제 쓰였는가

녹화된 로그만으로 실행을 되돌려 봅니다. **모델 호출이 0회**라서 몇 번을 돌려도 비용이 0입니다.

```
[▶ 재생] [↺] [8×▾] ├────────●──────────┤  68.4s / 136.8s

┌─ 스쿼드 맵 ────────────┐  ┌─ 경과 로그 ──────────┐
│  요청 → 플래너 → 에이전트 │  │ +0.0s  planning-started│
│         ↘ 집계 → 결과    │  │ +49.0s plan-ready      │
└────────────────────────┘  └──────────────────────┘

▒▒플래닝▒▒│░░승인 대기░░│███실행███│▓집계▓
Solver     ├──────█████████┤
                    ┃ 재생선
```

**조작**

| 하고 싶은 것 | 방법 |
|---|---|
| 전체 재생 | `▶ 재생` 버튼 |
| 특정 구간만 재생 | **맵의 노드**나 **아래 레인 막대**를 클릭 |
| 특정 시각으로 이동 | 슬라이더를 끌거나 **경과 로그의 줄을 클릭** |
| 속도 바꾸기 | `1× ~ 60×` 선택 |
| 맵 확대·이동 | 휠로 확대(0.25~6배), 드래그로 이동, `fit` 으로 초기화 |

**선택 상태가 네 화면에서 공유됩니다.** 맵 노드를 하나 고르면

1. 그 노드에 포커스 링이 켜지고
2. 아래 레인의 해당 막대가 강조되고 나머지는 흐려지고
3. 경과 로그가 그 시각으로 스크롤되고
4. **「장부 대조」 탭으로 가면 그 태스크의 응답이 강조돼 있습니다**

`Esc` 를 누르면 전부 해제됩니다.

**누적 토큰은 계단으로 오릅니다.** 보고된 시점에만 오르고 사이를 잇지 않습니다.
실측 첫 보고가 +84초인 실행도 있습니다. 그 사이를 이으면 로그에 없는 숫자를 지어내는 것입니다.

### 6-3. 장부 대조 — 채점기가 읽는 바이트가 무엇인가

왼쪽이 judge 가 보낸 **요청 원문**, 오른쪽이 우리가 낸 **응답**입니다.
**화면에 보이는 바이트가 로그에 기록된 그 바이트입니다.** 따로 수집한 요약이 아닙니다.

- 요청 쪽에서 `=== REQUIRED OUTPUT ===` 절과 마커가 **형광 표시**됩니다.
- 응답 쪽에서 **채점되는 구간**이 초록으로 표시됩니다.
- 그 아래에 검사 항목이 하나씩 나옵니다.

검사 결과는 **세 가지 모양**입니다. 색만 다른 것이 아니라 글리프가 다릅니다.

| 모양 | 뜻 |
|---|---|
| ✓ (초록 체크) | 통과 |
| ✗ (빨강 엑스) | 실패 |
| □ (빈 사각형) | **권장 항목이거나 판정 보류. 실패가 아닙니다** |

세 번째를 실패로 읽지 마십시오. 예를 들어 `FINAL ANSWER:` 접두사는 지문이 요구하지만
채점기가 실제로 요구하는지는 확인되지 않았습니다. 확인 안 된 것을 확정으로 적지 않습니다.

가운데 경계선을 **끌면 좌우 폭이 바뀝니다.** coding 문항은 요청이 60,000자까지 가니
왼쪽을 넓혀 두는 편이 낫습니다.

### 6-4. 타임라인 — 시간이 어디에 쓰였는가

- **위상 막대** — 플래닝 / 승인 대기 / 실행 / 집계.
  **승인 대기에는 빗금이 쳐져 있습니다.** `autoApprove: false` 인 실행에서 이건
  사람이 기다린 시간이지 시스템 성능이 아니기 때문입니다. 질감으로 "다른 종류"를 말합니다.
- **웨이브와 태스크** — 태스크마다 두 막대가 붙습니다. 빗금 막대가 **큐에서 기다린 시간**,
  꽉 찬 막대가 **실제로 돈 시간**입니다. 실측 대기 평균이 33초, 최대 361초입니다.
  실행 시간만 보고 있으면 병목을 통째로 놓칩니다.
- **세로 점선** — 워크스페이스에 파일이 쓰인 순간입니다.
- **이벤트 목록** — 오른쪽에 **결정 지점 배지**가 붙습니다
  (`계획` · `W1/2` · `파일 쓰기` · `토큰 보고` · `오류`).

### 6-5. 실패 분류 — 우리 잘못인가 인프라 잘못인가

맨 위에 **소유권 스택 막대**가 섭니다. 실패를 `FailureOwner` 네 값으로 나눕니다.

| owner | 뜻 | 색 |
|---|---|---|
| `configuration` | 우리 설정 문제 | 빨강 |
| `team` | 우리 문제 | 빨강 |
| `policy` | 요청 제한·시간 상한 | 노랑 |
| `organizer` | **주최 인프라 문제. 팀 책임이 아닙니다** | 중성 회색 |

> **`organizer` 를 빨강으로 칠하지 않습니다.** 팀 책임이 아닌 것을 팀 책임처럼 보이게 하면
> 화면이 틀린 말을 하는 것입니다.

아래에 실패마다 **에러 원문**이 그대로 붙습니다. 맨 아래 각주에 **분류 규칙표**가 있습니다.
접혀 있어도 "규칙표 있음"이 보입니다. 추측이 아니라 규칙이라는 걸 보이려고 그렇게 뒀습니다.

### 6-6. 원문 로그 — AI:GO 가 실제로 남긴 것

`<실행id>.jsonl` 을 줄 번호와 함께 그대로 보여줍니다. `error` 는 왼쪽 막대가 빨강,
`warn` 은 노랑입니다.

**`logs/index.json` 대조 카드**가 같이 나옵니다. 이 파일의 `entryCount` 는 실행 도중에
쓰이고 끝난 뒤 갱신되지 않아서 **직접 확인한 21건 전부에서 실제 줄 수보다 적었습니다.**
그래서 이 도구는 개수와 시각의 근거로 쓰지 않고, **이 실행이 어느 스쿼드 것인지만**
가져옵니다. 얼마나 어긋났는지는 화면에 적습니다.

## 7. 「전체 분석」 모드 — 절단선 실험대

첫 화면이 **절단선 실험대**입니다. 화면 폭 전체를 씁니다.

```
 채점 적격 ─┼──────●──●───●──────────────
            │                    ┃ 절단선
 불가      ─┼─●──●●───●──●───────┃──●────
            1      1.0k      10.0k     (로그 눈금)

 문항당 상한 ├────────────●─────────┤   8.0k tok

 절약 토큰        잃는 적격        잘리는 실행
 62.3k           1건              7건
 전체의 40.3%    적격 6건 중       전체 28건 중
```

**슬라이더를 끌어 보십시오.** 세 곳이 동시에 반응합니다.

1. 산점도의 절단선이 움직이고, 잘린 점이 **속 빈 점선 동그라미**로 바뀝니다
2. 아래 결과 계기 세 개가 다시 계산됩니다
3. **화면 맨 위의 CREDITS 계기가 실제로 줄어듭니다.** 잘려나간 칸은 빗금으로 남고,
   `CREDITS` 라벨이 두 번 깜빡여서 어디가 바뀌었는지 알려 줍니다

> **정직한 한계.** 상한에 닿는 순간 그 실행을 포기했다고 가정합니다. 잘린 실행의 적격은
> **전부 잃는 것으로** 계산하므로 이 숫자는 **손실의 상한**입니다. 실제 손실은 이보다 작습니다.

그 아래로 이어지는 화면들:

| 블록 | 무엇을 말하나 |
|---|---|
| **트랙별** | coding / math / generic 은 **요구하는 출력 형식이 다릅니다.** 합쳐 놓으면 어느 트랙이 새는지가 안 보입니다 |
| **스쿼드 라우팅** | 스쿼드가 스스로 찍은 트랙 vs 지문 기준. 마커를 남기는 스쿼드가 있을 때만 나옵니다 |
| **0점 4분류 스택** | 아래를 보십시오 |
| **전체 실행 간트** | 모든 실행을 한 시간축에. 빈칸은 아무도 일하지 않은 시간입니다 |
| **토큰 누적 곡선** | 계단이 가파른 구간이 비용이 몰린 곳입니다 |
| **응답 길이 대 적격** | 길게 쓴다고 맞는 게 아니라는 걸 보여줍니다 |
| **답 근접도** | 형식을 못 맞춘 실행이 얼마나 아까웠는지. 통과율이 높은 것부터 손대는 편이 빠릅니다 |

### 7-1. 0점 4분류 — 이 도구의 논지

**0점은 한 덩어리가 아닙니다. 네 갈래이고, 갈래마다 고칠 사람이 다릅니다.**

| 갈래 | 뜻 | 누가 고치나 |
|---|---|---|
| **호출 거부** | 모델이 요청을 받지도 못했습니다 (컨텍스트 초과·인프라) | **설정** |
| **판정 보류** | 트랙도 계약도 못 알아봤습니다 | **검사기** |
| **답 형식 없음** | 실행도 됐고 답도 나왔지만 형식이 안 나왔습니다 | **프롬프트** |
| **문항 아님** | 세 트랙 중 어느 형식도 아닙니다 (예: `"안녕"` 스모크 테스트) | 고칠 것이 없습니다 |

막대 각 구간 아래에 "누가 고치나"가 글자로 적혀 있습니다. **색만으로 뜻을 전달하지 않습니다.**

「문항 아님」은 0점의 갈래가 아니라 **채점 대상이 아닌 실행**입니다. 그래서 고칠 사람을
지목하는 셋 뒤, 적격 앞에 흐리게 섭니다.

「채점 적격」을 뺀 넷은 모두 **비율의 분모에서 뺍니다.** 우리가 고칠 수 있는 것만 놓고 비율을 냅니다.

> **한때 「계약 미전송」이라는 다섯 번째 갈래가 있었습니다. 없는 갈래였습니다.**
> 요청 원문에 계약 절이 없으면 러너가 안 보낸 것이라고 읽었는데, `history.json` 의
> `request` 는 모델에게 간 지문이 아니라 **질문만 잘라 저장한 값**이었습니다.
> 그렇게 분류된 8건의 요청이 83~499자였고(계약 절 하나가 250자입니다), 그중 6건의
> 응답에는 `\boxed{}` 가 들어 있었습니다. 모델은 형식을 들었습니다.
> 이 오분류가 **적격 6건을 0점으로 세고 있었습니다.**

## 8. 「스쿼드 비교」 모드

워크스페이스를 **두 개 이상** 넣었을 때만 의미가 있습니다.

스쿼드마다 카드가 하나씩 서고, 항목별 최고값에 **★** 가 붙습니다.

```
┌────────────────────┐
│▍LEDGER Squad       │
│ ikkim · 3f8a91c2   │
│ ▮▮▮▮▮  5명          │
│ 채점 적격  ★ 6 / 7  │
│ ▓▓▓▓▓▓▓▓░           │
│ 문항당 토큰  ★ 12k  │
│ 문항당 시간    8.2s │
│ 실제 실행 시간 6.0s │
└────────────────────┘
```

- 이름 아래에 **워크스페이스와 `squadId` 앞 8자**를 같이 적습니다.
  이름만으로는 두 스쿼드가 같은 것인지 알 수 없습니다.
  실측으로 **한 워크스페이스에서 스쿼드 넷이 돈 경우**가 있었습니다.
- 로스터는 **도트 아바타 줄**로 압축됩니다. 이름은 마우스를 올리면 나옵니다.
- 아래에 **같은 문항 비교**가 전폭으로 붙습니다. 조건이 같으니 차이가 곧 스쿼드 차이입니다.

> **문항당 시간에는 승인 대기가 들어 있습니다.** `autoApprove:false` 인 실행에서는
> 사람이 기다린 시간이라 시스템 성능이 아닙니다. 그래서 **실제 실행 시간**을 따로 뒀습니다.

## 11. 색과 모양이 뜻하는 것

색이 **세 층**으로 나뉩니다. 층마다 뜻이 다르고 서로 섞이지 않습니다.

### 11-1. 판정색 — 어디서나 같은 뜻

| 판정 | 색 | 왜 이 색인가 |
|---|---|---|
| **채점 적격** | 라임 | 유일하게 점수가 되는 상태 |
| **답 형식 없음** | 코랄(빨강) | **우리가 프롬프트로 고칠 수 있는 영역** |
| **실행 불가** | 골드(노랑) | 우리 밖의 원인입니다. 경고이지 실패가 아닙니다 |
| **판정 보류** | 중성 회색 | 모르는 것에 색을 주면 안다는 뜻이 됩니다 |

**빨강은 일부러 「답 형식 없음」에만 씁니다.** 네 갈래 중 우리가 손댈 수 있는
하나를 색으로 지목하는 것입니다.

### 11-2. 계열색 — 스쿼드 구분

목록 왼쪽 세로 막대, 산점도의 점, 곡선에 쓰입니다. **판정과 아무 관계가 없습니다.**

### 11-3. 트랙 — 색을 쓰지 않습니다

트랙은 **도트 글리프 + 테두리 + 라벨**로 구분합니다.

| 트랙 | 글리프 | 출력 계약 |
|---|---|---|
| coding | `<>` | `*** PATCH START ***` … `*** PATCH END ***` |
| math | `∑` | `FINAL ANSWER: \boxed{<answer>}` |
| generic | 체크박스 | `ANSWER: <letter>` |
| unknown | `?` | — |

> **왜 트랙에서 색을 뺐나요?**
> 목록 한 행에 트랙 배지와 판정 배지가 나란히 서면, 같은 초록이 "math" 와 "적격"
> 두 가지 뜻을 갖게 됩니다. 그러면 화면을 한눈에 읽을 수 없습니다.

### 11-4. 질감

| 질감 | 뜻 |
|---|---|
| **빗금(디더)** | "이건 실행이 아니다" — 승인 대기, 큐 대기, 미참여 에이전트, 잘려나간 크레딧 칸 |
| **셀 게이지** | 진행률. 연속 막대가 아니라 칸으로 셉니다 |
| **회전한 도장** | 판정. 한국어가 주, 영문이 보조입니다 |

## 12. 내보내기

### 12-1. JSON

`JSON` 버튼을 누르면 `monstrous-normalized.json` 이 저장됩니다. 안에 든 것:

- 스쿼드별 로스터 (이름·역할·모델·도구·태스크 수·실패 수·추정 토큰)
- 실행별 id · 워크스페이스 · 계약 · `gradable` · `blocker` · 토큰 · 소요 · 위상
- 태스크별 검사 결과 전부

**이 파일이 이 도구의 회귀 검사 기준이기도 합니다.** 화면을 아무리 바꿔도 같은
워크스페이스에서 나오는 이 파일은 바이트 하나 달라지지 않아야 합니다.

### 12-2. SVG

`SVG` 버튼은 지금 화면에서 **가장 큰 그림 하나**를 골라 저장합니다.
CSS 변수를 실제 색으로 굳혀서 내보내므로 다른 곳에서 열어도 색이 유지됩니다.

## 13. 이 도구가 일부러 안 하는 것

| 안 하는 것 | 왜 |
|---|---|
| 실시간 모니터링 | 시연 중 네트워크가 죽으면 화면도 죽습니다. 재생 모드가 그 자리를 대신합니다 |
| 리더보드 대비 위치 | 네트워크 의존이 생깁니다 |
| 캐시 히트율·모델별 비용 | **로그에 필드가 없습니다.** 그리면 숫자를 지어내는 것입니다 |
| 실패를 벌칙처럼 연출 | 실패의 상당수가 주최 인프라 책임입니다. "GAME OVER" 는 틀린 말을 하는 화면입니다 |
| 용어를 게임 어휘로 교체 | `실행` 은 `실행`, `웨이브` 는 `웨이브`. 화면 단어를 문서와 대조할 수 있어야 합니다 |

## 14. 문제가 생겼을 때

### 14-1. "파일 N개를 읽었지만 실행을 세우지 못했습니다"

`logs/` 안의 파일이 일부만 들어왔을 때 나옵니다.
**최소한 `history.json` 과 `events.jsonl` 이 함께 들어와야 합니다.**
화면 아래에 무엇이 읽혔는지 목록이 나오니 확인해 보십시오.

### 14-2. 실행은 보이는데 응답 원문이 비어 있습니다

`history.json` 없이 `events.jsonl` 만 들어온 경우입니다.
「부분 기록」으로 표시되고, **불합격으로 적히지 않습니다.**

### 14-3. 스쿼드 구성에 사람이 모자랍니다

로그에는 **태스크를 배정받은 에이전트만** 남습니다. 한 번도 일하지 않은 구성원과
플래너는 로그만으로 존재를 알 수 없습니다.
**`.squad.json` 을 같이 넣으십시오.** 그 파일이 로스터의 유일한 정답입니다.

### 14-4. 여러 스쿼드가 한 덩어리로 보입니다

묶는 단위는 워크스페이스가 아니라 **`squadId`** 입니다. 한 워크스페이스에서 스쿼드가
여러 번 바뀌었다면 카드도 여러 장 섭니다. 카드의 `squadId` 앞 8자로 구분하십시오.

### 14-5. 화면이 옛날 그대로입니다

`src/app.html` 만 고치고 빌드를 안 돌린 경우입니다.

```bash
bash viz_revise_program/tools/build.sh
```

이 스크립트가 검사를 통과시킨 뒤 `trace-visualizer.html` 을 다시 만듭니다.
**산출물을 직접 고치지 마십시오.** 다음 빌드에서 덮어써집니다.

### 14-6. 브라우저가 파일을 못 엽니다

일부 브라우저는 `file://` 에서 로컬 폴더 읽기를 제한합니다. 그럴 때는
저장소 루트에서 간단한 로컬 서버를 띄우십시오.

```bash
python3 -m http.server 8777
# 그 다음 http://127.0.0.1:8777/viz_revise_program/trace-visualizer.html
```

### 14-7. 실행이 수백 건이라 목록이 느립니다

느리지 않습니다. 200건씩 끊어 그립니다. 직접 재 보니 실행 1,000건에서
목록 렌더가 **11ms**, 검색 입력 응답이 **14ms** 였습니다.
그래도 느리면 상단 필터로 부분집합을 먼저 좁히십시오.

## 15. 자동 시연 — `#demo`

1분짜리 시연 영상을 찍을 때 사람이 클릭할 시간이 없습니다. 주소 끝에 `#demo` 를 붙여
열고 폴더를 넣으면, 그 순간부터 **60초 동안 스스로 돌면서** 화면 아래 자막을 바꿉니다.

```
trace-visualizer.html#demo
```

| 시각 | 화면 | 자막 |
|---|---|---|
| 0:00 | 실행 하나 (선택 없음) | 폴더 하나. 설치도 서버도 없습니다 |
| 0:06 | 계기 띠 | AI:GO 는 N건이 성공이라고 적었습니다. 점수가 되는 건 M건입니다 |
| 0:14 | 전체 분석 · 0점 갈래 | 0점은 한 덩어리가 아닙니다. 갈래마다 고칠 사람이 다릅니다 |
| 0:22 | 전체 분석 · 트랙별 | 트랙마다 요구하는 출력 형식이 다릅니다 |
| 0:29 | 개요 (고른 실행) | *데이터에 따라 달라집니다 — 아래 참고* |
| 0:40 | ▶ 재생 (자동 재생) | 녹화된 로그만으로 재생합니다. 모델 호출 0회 |
| 0:49 | 전체 분석 · 절단선 | 상한을 걸면 얼마를 아끼고 무엇을 잃는지 즉시 계산합니다 |
| 0:56 | — | 로그에 있는 것만 씁니다 |

자막 위의 가는 선이 남은 시간입니다. 60초가 지나면 자막이 사라지고 화면은 그대로 남습니다.

### 실행을 id 로 고르지 않습니다

촬영 데이터가 그때그때 다르기 때문입니다. 0:29 의 실행은 **성격으로** 찾고, 없으면
다음 후보로 내려갑니다.

1. 라우팅이 어긋났고 값은 맞은 실행 — 할 이야기가 가장 많습니다
2. 값은 맞았는데 형식 때문에 0점인 실행
3. 라우팅만 어긋난 실행
4. 형식을 못 맞춘 실행
5. 호출 자체가 거부된 실행
6. 그것도 없으면 아무거나 — 적격이라도 보여줍니다

자막도 고른 실행에 맞춰 바뀝니다. **어떤 워크스페이스를 넣어도 같은 이야기가 나오고,
숫자만 그 데이터의 것으로 바뀝니다.**

- 언어는 `#demo&l=en` 으로 같이 정할 수 있습니다. 자막도 그 언어로 나옵니다
- 폴더를 넣는 장면부터 찍으면 첫 자막이 그 위에 자연스럽게 붙습니다
