## 1. 로직 무결성 — 가장 중요한 게이트

### 1-1. JSON 내보내기 바이트 동일

기획 `03 §4-1` 이 정한 기준선이다. **같은 워크스페이스를 넣고 `JSON` 내보내기를 눌렀을 때
개편 전후의 파일이 바이트 동일해야 한다.**

| | 개편 전 `viz/trace-visualizer.html` | 개편 후 `viz_revise_program/` |
|---|---|---|
| 실행 수 | 30 | 30 |
| 읽은 파일 | 299 | 299 |
| **바이트** | **90,128** | **90,128** |
| **해시** | **2136881638** | **2136881638** |
| 판정 분포 | blocked 5 · nocontract 10 · markers 9 · ok 6 | **동일** |

**동일.** 화면을 전부 갈아엎었는데 정규화 데이터는 한 바이트도 안 바뀌었다.

> **입력을 먼저 얼려야 한다.** 처음에는 `squad/` 를 직접 넣고 쟀는데 두 번째 측정에서

> 새로 생겨 있었다** — 다른 작업이 같은 폴더에 쓰고 있었다.

## 3. HUD 폭 — 겹치지도, 잘리지도 않는다

**처음 검증은 「겹침」만 봤고 「잘림」을 안 봤다.** 그래서 1440px 에서 「AI:GO 성공 ⇄ 채점 적격」의
오른쪽 숫자가 잘려 있는 것을 놓쳤다 — 한국어에서 4px, 영어에서 30px. 영어에서는 숫자가
통째로 사라진 상태였고, 그게 이 도구의 논점이 되는 숫자다.

원인은 계기가 `flex-shrink` 기본값이었던 것이다. 폭이 몇 px 모자라면 계기가 사라지는 대신
상자만 좁아지고 `overflow:hidden` 이 값을 잘랐다. `flex:none` 으로 바꾸고 계기 간격을
24px → 12px 로 줄인 뒤, 숨기는 경계값을 **영어 라벨 기준**으로 다시 잡았다.

검사 방법도 바꿨다. 겹침이 아니라 계기마다 `scrollWidth − clientWidth` 를 잰다.
0 이 아니면 그 계기는 잘린 것이다.

| 뷰포트 | 보이는 계기 (한/영 동일) | 잘림 (`scrollWidth − clientWidth`) | 조작부 높이 |
|---|---|---|---|
| 1920 | 실행 · ⇄ · CREDITS · TIME | 0 / 0 / 0 / 0 | 97px |
| 1600 | 4개 전부 | 0 / 0 / 0 / 0 | 97px |
| 1440 | 실행 · ⇄ · **CREDITS** | 0 / 0 / 0 | 97px |
| 1280 | ⇄ · **CREDITS** | 0 / 0 | 97px |
| 1024 | **CREDITS** | 0 | 97px |
| 1440 발표 모드 | 실행 · ⇄ · **CREDITS** | 0 / 0 / 0 | 98px |

1440px 실측 예산(영어): 워드마크 168 + 계기 89·229·310·103 + 간격 12×3 + 도구 473 +
좌우 여백·열 간격 64 = **1471**. 1440 에 31px 이 모자라므로 TIME 이 먼저 빠진다.

**숨는 순서는 TIME → 실행 → 대조 계기이고 CREDITS 가 마지막까지 남는다.** 환산
비율(`1칸 = 8.0k tok`)을 화면에서 빼면 칸이 단위를 지어내는 것이 되기 때문이다.

> **1440 에서 TIME 이 빠지는 것은 맞바꾼 결과다.** 넷을 다 세우려면 31px 을 어디선가
> 빼야 하는데, 그 여유는 숫자가 한 자리만 늘어도 사라진다. 잘린 숫자보다 사라진 계기가
> 정직하다 — 사라진 것은 사라진 줄 알지만, 잘린 숫자는 다른 숫자로 읽힌다.

## 5. i18n

영어 모드에서 **실행 28건 × 탭 6개 × 모드 3개**, 각주를 전부 편 상태로 `i18nAudit()` 을 돌렸다.

| | 값 |
|---|---|
| 한국어가 남은 문자열 (전체) | 102 |
| 그중 **로그 데이터** | 102 |
| 그중 **UI 문구** | **0** |

로그 데이터는 번역 대상이 아니다. 그건 로그의 내용이지 UI 가 아니다.
남은 102개는 전부 에이전트 이름(`보안 리뷰어` · `백엔드 개발자`)과 태스크 제목,
요청 원문이다. 화면이 만든 문구와 붙어 한 덩어리로 잡히는 것들이라
(`보안 리뷰어: For how many real values… Runs 180.3s`) 처음에는 UI 잔존으로 보였는데,
조각을 갈라 보면 한국어 부분이 전부 로그의 값이다.

### 5-1. `aria-label` 도 번역된다

`i18nAudit()` 은 텍스트 노드만 본다. 눈에 안 보이는 `aria-label` 은 그 검사를 그냥 통과한다.
따로 확인했다.

| 요소 | 한국어 | 영어 |
|---|---|---|
| `#list` | 실행 목록 | **Run list** |
| `#help` | 단축키 | **Shortcuts** |

## 7. 인쇄

`printBackground:false` — 브라우저의 「배경 그림 인쇄」가 꺼진 기본 설정 — 로 A4 PDF 를
실제로 뽑아 확인했다. 3쪽, 282KB.

| 항목 | 결과 |
|---|---|
| 종이 바탕 | 흰색 |
| 본문 글자 | 검정 (`--fg` 를 인쇄 블록에서 뒤집는다) |
| 판정 도장 | 테두리 + 글자만 (그림자·회전 없음) |
| 셀 게이지 · 위상 막대 · 스택 막대 | 채움이 그대로 나온다 (`print-color-adjust:exact`) |
| 접힌 각주 | 전부 펴짐 |
| HUD 도구 줄 · 좌측 목록 · 조작 띠 | 안 나옴 |
| `tools/contrast.py` | 인쇄 팔레트도 같이 검사한다 — 검사한 블록 **5개**, 위반 0건 |

**고치기 전에는 검은 종이 아니면 백지였다.** 초안은 `body` 색만 뒤집어서 패널·표·HUD 는

남았다. 자세한 것은 `00-작업-기록.md` §5-3 의 27번.

## 9. 아직 확인하지 못한 것

정직하게 적는다.

| 항목 | 왜 못 했나 |
|---|---|
| **「판정 보류」(`blocker==="unknown"`) 상태** | 지금 저장소의 워크스페이스 30건에 이 상태가 **하나도 없다.** 코드 경로는 있고 문자열도 사전에 있지만 화면으로 확인하지 못했다 |
| 재생 60fps · 드롭 프레임 0 | Performance 패널 기록이 필요하다. 시계는 `RP.step()` 으로 검증했다 |
| 실제 프로젝터 시연 | 고대비 모드의 명암비는 계산·검사로만 확인했다 |
| 종이 인쇄 | PDF 는 실제로 뽑아 확인했다 (§7). 잉크로 찍은 결과는 못 봤다 |
| Firefox · Safari | Chromium 에서만 돌렸다. 슬라이더는 `::-moz-` 규칙을 따로 써 뒀지만 눈으로 못 봤다 |
| 워크스페이스 1개만 넣은 경우 | 「스쿼드 비교」 안내 문구 경로. 코드에는 있다 |

**첫 항목이 가장 아쉽다.** 「판정 보류」는 이 도구의 4분류 중 하나이고,
"모르는 것을 불합격으로 적지 않는다"는 원칙이 눈에 보이는 자리다.
계약이 불명한 실행이 들어오는 워크스페이스가 생기면 그때 확인해야 한다.
