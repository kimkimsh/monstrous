# 02. 스펙에서 벗어난 것 — 무엇을, 왜

`docs/viz_revise/spec/` 은 정본이다. 구현이 스펙과 다르면 **구현이 틀린 것이거나
스펙이 틀린 것이고, 둘 중 어느 쪽인지 적지 않으면 다음 사람이 다시 판단해야 한다.**

아래는 전부 **의도적으로** 벗어난 것이다. 각 항목에 확인 방법을 같이 적는다.

---

## A. 스펙 값이 실제로 틀렸던 것

### A-1. `--ease-pop` 의 오버슈트

| | 값 |
|---|---|
| 스펙 (`00 §1`, `02 §2`) | `cubic-bezier(0.34, 1.4, 0.5, 1)`, "오버슈트 12%" |
| 실제 최고점 | **1.0529** (t≈0.65) → 5.3% |
| 스펙이 정한 대역 (`02 §1`) | **8~12%** |
| 구현 | `cubic-bezier(0.34, 1.56, 0.64, 1)` → 최고점 **1.098** (9.8%) |

**확인:** 3차 베지어 y(t) = 3(1−t)²t·y₁ + 3(1−t)t²·y₂ + t³.
y₁=1.4, y₂=1 일 때 t=0.6 → 1.0512, t=0.65 → 1.0526, t=0.7 → 1.0486.
스펙 값은 자기가 정한 하한(8%)에도 못 미쳤다.

### A-2. 셀 게이지 채움 시간

| | 값 |
|---|---|
| 스펙 (`02 §3`) | 220ms 고정 |
| 20칸에 나누면 | **칸당 11ms** |
| 60Hz 한 프레임 | 16.7ms |

칸당 시간이 한 프레임보다 짧으면 "칸이 하나씩 켜진다"가 물리적으로 불가능하다.
게다가 `--ease`(outQuint) 는 앞을 몰아 써서 첫 프레임에 네 칸이 한꺼번에 켜진다.

**구현:** 칸당 28ms · `linear` · JS 가 변화량에 비례해 `--t-gauge` 를 넣는다 (상한 420ms).
많이 자를수록 오래 걸리는 쪽이 정직하기도 하다.

```js
el.style.setProperty("--t-gauge", Math.min(420, Math.abs(on-prev)*28)+"ms");
```

### A-3. 포커스 링이 눌린 버튼 위에서 사라진다

`--focus`(GOLD `#FFC24B`) 를 `button[aria-pressed="true"]` 의 EMBER 채움(`#FF8A3D`) 위에 두면
**1.46:1**. WCAG 2.2 SC 1.4.11 은 3:1 을 요구한다. 상태를 나타내는 바로 그 조작부에서
링이 안 보인다.

**구현:** `outline-offset` 이 만든 2px 틈을 `--ink` 로 채운다.

```css
:focus-visible{outline:2px solid var(--focus);outline-offset:2px;box-shadow:0 0 0 2px var(--ink)}
```

ink-vs-gold **11.4:1**, ink-vs-ember **7.8:1**. 두 모서리가 각각 다른 배경에서 산다.
반지름 0 이라 퍼짐만 준 `box-shadow` 는 정확한 사각형이므로 모양 손해가 없다.

### A-4. 스펙의 `--dim-c` 가 정의돼 있지 않다

`01 §4-1` 이 `var(--dim-c, transparent)` 를 쓰는데 `--dim-c` 는 스펙 어디에도 없다.
폴백이 `transparent` 라 **잘린 칸이 그냥 사라진다** — `03 §1-2` 의
"원래 값이 사라지면 실험이 실험으로 안 읽힌다"와 정면으로 어긋난다.

또 `.gauge.has-dim` 의 45° 빗금이 `background-image` 로 **요소 전체**에 깔려
켜진 칸까지 덮는다.

**구현:** 잘린 구간만 `::before` 로 그린다. 부모의 `mask` 가 자손까지 함께 자르므로
칸 사이 간격은 저절로 맞는다.

### A-5. 목록 게이지의 칸 수가 선형이면 대부분 0칸

`03 §3-1` 의 `--on = round(billed/maxTok*12)`.

과금 토큰은 1k~1M 로 세 자리수 넘게 벌어진다 (같은 문서가 산점도를 **log10** 축으로 그린다).
실측 12.4k 실행을 최대 1M 기준으로 넣으면 `round(0.1488)` = **0칸**.

**구현:** 위에서 세 자리수를 창으로 잡는 로그 눈금. 그 아래는 전부 1칸으로 바닥을 깐다.

```js
const CELL_DECADES=3;
function cellsLog(v,max,n){
  if(!(v>0)) return 0;
  const hi=Math.log10(Math.max(10,max));
  const p=(Math.log10(v)-(hi-CELL_DECADES))/CELL_DECADES;
  return Math.max(1,Math.min(n,Math.round(p*n)));
}
```

실제 숫자는 언제나 옆에 같이 적는다. 칸은 크기 감각을 주는 보조 표기다.

### A-6. `micro`(10px) 를 HTML 텍스트에 쓴 곳

`00 §3-1` 이 "`micro` 는 SVG 안에서만, HTML 텍스트의 하한은 `caption` 11px" 라고 못 박았는데,
`01 §5` 의 `.stamp em` 과 `01 §11` 의 `.stack em` 이 둘 다 HTML 이면서 `--fs-micro` + `opacity` 다.

`.stack em` 은 "누가 고치나" 라벨이다 — 색만으로는 알 수 없는 것을 글자로 적는 자리인데,
`--ink` 를 75% 로 깔면 라이트 GOLD 위에서 **3.96:1** 로 떨어진다.
`contrast.py` 는 선언된 토큰 쌍만 보므로 합성된 알파를 **구조적으로 못 잡는다.**

**구현:** 둘 다 `--fs-caption`(11px) 로 올리고 `opacity` 를 없앴다. 약하게 보이는 것은
`--fg-faint` 같은 이미 검증된 토큰으로 낸다.

## B. 한국어 조판 때문에 벗어난 것

### B-1. 자간은 라틴 전용

`01 §13` 이 "한국어 라벨은 `text-transform` 이 무의미하지만 해가 없다"고 적었다.
대문자화는 그렇지만 **`.16em` 자간은 해가 있다.** 한글 음절은 이미 제 사이드베어링을
갖고 있어서, 자간을 걸면 `채 점 적 격` 으로 읽힌다.

**구현:** `.stat-k` · `th` · `.sec-t` · `.kv dt` 등 한글이 들어오는 라벨은 `--font-ui`, 자간 0.
자간·대문자화·디스플레이 글꼴은 `.lat` 클래스에만 건다 (`CREDITS` · `TIME` · `GRADED` · 트랙명).

덤으로, 자간은 마지막 글리프 **뒤에도** 붙어서 가운데 정렬한 라벨을 왼쪽으로 민다.
반지름 0 격자에서는 상자 모서리가 정렬 기준이라 이 어긋남이 바로 보인다.

```css
.stamp em{letter-spacing:.2em;margin-right:calc(-1 * .2em)}
```

### B-2. `word-break:keep-all`

한글은 기본이 음절 단위 줄바꿈이라 좁은 표 칸에서 `실행 불가` 가 `실행 불 / 가` 로 쪼개진다.
스펙에는 이 항목이 없다.

### B-3. 고정폭 글꼴의 합자를 끈다

`--font-mono` 스택에 JetBrains Mono 가 들어 있다. 이 폰트의 합자는 `!=` 와 `=======` 를
**다시 그린다.** 그 바이트가 곧 증거인 도구에서 합자는 증거를 위조하는 것과 같다.

```css
code,pre,kbd{font-variant-ligatures:none}
```

## C. 구조 때문에 벗어난 것

### C-1. 도트 글리프를 전부 12×12 로 통일

스펙 `01 §6-1` 은 글리프마다 viewBox 가 다르다 (`0 0 8 7`, `0 0 7 7`, `0 0 5 7`).
전부 `width="12"` 로 내면 배율이 1.714 · 1.714 · 2.4 로 제각각이라
`shape-rendering:crispEdges` 가 도트 줄마다 1px 과 2px 로 다르게 스냅한다.
**같은 배지 안에서 `∑` 와 `<>` 의 굵기가 달라진다.**

**구현:** 전부 12×12 격자에 다시 그리고 12px 또는 24px 로만 낸다. 1 유닛 = 1 픽셀.
그림은 좌표 목록이 아니라 **행 문자열**로 적어서 소스에서 그대로 보인다.

```js
coding:["............","............","............",
        "....#..#....","...#....#...","..#......#..", …]
```

### C-2. 셀 폭을 고정한다

스펙은 `calc(100% / var(--cells))`. 그러면 칸 폭이 소수점이 되어 마스크의 하드 엣지가
칸마다 다르게 안티에일리어싱되고, 목록을 스크롤할 때 막대가 아른거린다.
하드 엣지가 정체성인 화면에서 아른거리는 엣지는 실패다.

**구현:** `--cell-pitch:8px` 고정. 슬라이더 트랙(`6px/8px`)과 같은 피치라
HUD 에서 두 계기가 같은 리듬으로 선다. 게이지 폭 = 칸 수 × 피치
(HUD 20칸=160px · 목록 12칸=96px · 패널 16칸=128px · 격자 8칸=64px).

### C-3. 컨테이너 질의

`02 §5-4` 는 "뷰포트가 아니라 컨테이너 폭으로 접는다"고 적었는데
`03 §7` 은 전부 `@media` 다. 사이드바가 180~720px 이라 1280px 창에서도
장부 대조 칸이 270px 이 될 수 있다.

**구현:** `.pane{container-type:inline-size}` + `@container` 로 장부·결론 층을 접는다.
HUD 계기 숨김은 창 폭이 기준이라 `@media` 로 남겼다.

### C-4. HUD 계기가 사라지는 순서

`01 §16-0` 의 CSS 는 4번 → 2번 순으로 숨긴다. 그런데 2번은 `AI:GO ⇄ 채점 적격` —
기획 `00 §5-1` 이 **"이 도구의 논점"** 이라고 부른 계기다. 같은 절의 산문은
"크레딧과 실행 수는 마지막까지 남는다"고 적어 CSS 와 어긋난다.

**구현:** TIME(4번) → 실행(1번) 순으로 숨긴다. **⇄ 와 CREDITS 는 끝까지 남는다.**
안전망으로 `.hud .stat{overflow:hidden}` 을 걸어 어떤 경우에도 계기가 서로 겹치지 않게 했다.

### C-5. `.hud-2` 의 세로 패딩은 0

`01 §16-2` 는 `padding:var(--s1) var(--s4)` + `min-height:40px`. 그런데 버튼이 40px 이라
실제 높이가 **49px** 이 되고 조작부 합계가 105px 로 상한(100px)을 넘는다.

**구현:** 세로 패딩 0. 40 + 테두리 1 = **41px**. 히트 영역은 버튼 자체가 40px 이라 그대로다.

### C-6. `.panel` 진입 애니메이션을 뺐다

`02 §4-5` 는 패널마다 260ms 진입. 그런데 탭 전환은 스펙 자신의 `§5` 표에서 **F0(애니메이션 0)**
이고, 패널 하나가 아니라 한 화면에 4~6장이 있다. 마우스로 탭을 누를 때마다
본문 전체가 260ms 떤다. `both` 채우기라 첫 프레임이 `opacity:0` 이어서,
차트를 다시 그리는 프레임과 겹치면 빈 화면이 보인다.

**구현:** 패널 진입 없음. 대신 **모드 전환(F2)** 에만 `.pane` 불투명도 페이드 180ms.

### C-7. 도장은 결론 층에서만 찍힌다

`02 §5` 는 도장을 F3(드물게)로 분류하는데, 장부 탭은 응답 후보마다 도장이 선다.
전부 찍히면 "드물게"가 아니다.

**구현:** `.verdict .stamp` 만 애니메이션. 목록·장부·비교의 작은 도장은 `animation:none`.
키프레임도 고쳤다 — 진입 구간은 가속 곡선, 착지 구간은 감속 곡선을 써서
방향이 한 번만 바뀐다. 오버슈트 곡선을 이미 오버슈트하는 키프레임 사이에 걸면
고무공처럼 읽힌다. 접촉은 38% × 240ms = **91ms**, 그림자는 **90ms** 에 들어온다.

### C-8. 스캔라인을 오버레이가 아니라 바탕으로

`00 §4-3` 은 `.cabinet::after{position:absolute;inset:0}` 로 겹친다.
1px 주기 오버레이가 차트의 1px 격자선·10px 라벨과 간섭해서
**화면에서 가장 작은 글자의 명암비를 깎는다.**

**구현:** `body` 의 `background-image` 로 넣는다. 패널이 불투명하므로 결과적으로
캐비닛 바깥에만 보이고, 어떤 텍스트 위에도 겹치지 않는다.

## D. 보존 구간 때문에 벗어난 것

### D-1. `S.focus` · `S.fnOpen` 을 블록 밖에서 얹는다

`03 §0` 은 `S` 선언에 필드 두 개를 더하라고 하지만 `const S={…}` 는 보존 구간 안에 있다.
바깥에서 `S.focus=null; S.fnOpen=new Set();` 로 얹었다. 결과는 같고 보존은 지켜진다.

### D-2. 옛 색 토큰 별칭 넷

보존된 SVG 내보내기가 `--ok` · `--warn` · `--bad` · `--prog` 를 **이름으로** 읽는다.
지우면 내보낸 그림의 색이 빈 값이 된다. 토큰 블록에 별칭으로 남기고 주석을 달았다.
화면 규약은 어디까지나 판정 4색이다.

### D-3. `att()` 신설

`esc()` 는 보존 구간 함수라 `& < >` 만 바꾼다. 요청 지문에 `"` 가 흔해서
`title="${esc(...)}"` 가 깨진다. 신규 코드에 속성 전용 이스케이프를 하나 만들었다.

## E. 클래스 이름 사고 — 기록해 둔다

스펙 `04 §2-4` 는 `sm-` 을 스쿼드 맵 접두로 정했고, 맵 SVG 자체는 현행대로 `.sm` 이었다.
작은 도장의 수식자로 `.sm` 을 쓰자 **글자가 같아서 충돌했다** —
`.sm{display:block;width:100%}` 가 도장에 그대로 걸려 목록의 도장이 행 폭 전체로 늘어났다.

`getComputedStyle` 로 보면 `display:block`, 폭 203px. 원인을 찾는 데 시간이 걸렸다.
CSS 는 이름이 같으면 그냥 같은 것으로 취급한다.

**구현:** 맵 SVG 를 `.sm-svg` 로 옮겼다 (이미 쓰던 `sm-` 이름 공간 안이다).
**한 글자·두 글자짜리 클래스 이름은 쓰지 않는다.**
