## 4. 구현 중에 내린 결정

### 4-1. `S` 에 필드를 더하는 방법

스펙 `03 §0` 은 `S` 에 `focus` 와 `fnOpen` 을 더하라고 한다. 그런데 `const S={…}` 는
**보존 구간(`model`) 안**에 있어서 거기서는 못 고친다.

→ 보존 블록을 그대로 두고, **블록 바깥에서 속성을 얹었다.**

```js
S.focus=null;
S.fnOpen=new Set();
```

### 4-2. 위상 색과 트랙 색

`phasesOf()` 는 보존 대상이라 옛 변수 이름(`var(--prog)` 등)을 그대로 돌려준다.
새 토큰에는 그 이름이 없다.

→ 반환값의 `.c` 를 **쓰지 않고**, 위상 이름으로 새 토큰에 매핑하는 표(`PHASE_COLOR`)를 뒀다.
위상 이름은 사실상 열거형이라 이 표가 유일한 접점이다.
`TRACK[k].c` 도 같은 이유로 안 쓴다 — 새 규약에서 트랙은 색을 쓰지 않는다.

### 4-3. 내보내기가 읽는 옛 토큰

보존된 SVG 내보내기 코드가 `--ok` · `--warn` · `--bad` · `--prog` 를 **이름으로** 읽는다.
지우면 내보낸 그림의 색이 빈 값이 된다.

→ 토큰 블록에 호환용 별칭 넷을 남기고, 왜 남겼는지 주석으로 적었다.
화면 규약은 어디까지나 판정 4색이다.

### 4-4. `esc()` 로는 속성을 못 막는다

`esc()` 는 보존 구간 함수라 `& < >` 만 바꾼다. 요청 지문에 `"` 가 흔해서
`title="${esc(...)}"` 가 통째로 깨진다.

→ 신규 코드에 `att()` 를 만들어 속성 자리에서만 쓴다. 보존 함수는 안 건드렸다.

### 5-1. 결함 9 — 실측

`j` 로 실행을 훑으면 패널이 매번 다시 그려진다. 재생 탭의 맵 확대·이동과 장부 탭의
폭 손잡이가 각각 `window` 에 `mousemove` 와 `mouseup` 을 달고 있었는데, **떼지 않았다.**

| | 리스너 수 |
|---|---|
| 재생·장부 20회 렌더 (고치기 전) | **40** |
| 같은 조건 (고친 뒤) | **2** |

`mousemove` 하나가 `getScreenCTM()` 과 행렬 역변환을 돈다. 200건을 훑고 나면
마우스를 한 번 움직일 때마다 그게 400번 돈다. 심사 시연 중에 눈에 보이게 느려지는 종류다.

고친 방법 — 패널을 새로 그릴 때 앞의 신호를 끊는다.

```js
let PANE_AC=null;
function paneScope(){
  if(PANE_AC) PANE_AC.abort();
  PANE_AC=new AbortController();
  return PANE_AC.signal;
}
// 패널 안에서 window 에 다는 것만 묶는다.
// 요소에 직접 단 리스너는 DOM 이 사라질 때 같이 사라진다.
addEventListener("mousemove", …, {signal:S.paneSignal});
```

끊는 시점이 너무 이르지 않은지도 확인했다 — 고친 뒤에도 맵 드래그가 그대로 동작한다.

## 기준선 재수립 1회 (계약 판정 정정)

개편 이후에 판정 로직이 두 번 바뀌었다. 보존 구간 `contract` · `model` 을 다시 떴다.
`failure` · `collect` · `i18n` · `load` · `export` 는 손대지 않았다.

### 무엇이 바뀌었나

**1. 「문항 아님」 갈래 추가**

`test_4` 의 실행 10건이 전부 요청이 `"안녕"` 두 글자였다. 스모크 테스트다.
그런데 전부 「계약 미전송」으로 세여서 그 숫자가 8에서 18로 뛰었다 —
러너가 계약을 열 번 더 빠뜨린 것처럼 읽힌다. 아무도 빠뜨리지 않았다.

세 트랙 중 어느 형식도 아닌 지문은 벤치마크 문항이 아니다. 분모에서 빠지는 것은
다른 갈래와 같지만, 고칠 사람을 지목하는 셋과는 자리를 가른다 — 여기엔 고칠 것이 없다.

**2. 「계약 미전송」 갈래 삭제**

이게 더 큰 정정이다. 그런 갈래는 애초에 존재하지 않았다.

`=== REQUIRED OUTPUT ===` 절이 요청 원문에 없으면 "모델이 형식을 들은 적이 없다"고
읽었다. 틀렸다. `history.json` 의 `request` 는 모델에게 간 지문이 아니라
**질문만 잘라 저장한 값**이다.

근거 둘:

- 그렇게 분류된 실행 8건의 `request` 가 **83~499자**였다. 계약 절 하나가 250자다.
  애초에 들어갈 자리가 없었다.
- 그중 **6건의 응답에 `\boxed{}` 가 들어 있었다.** 한 건은 `FINAL ANSWER: \boxed{}`
  형태까지 갖췄다. 모델은 형식을 들었다.

계약은 트랙마다 하나씩이고 세 트랙 모두 언제나 붙어서 나간다.
그래서 계약 절이 안 보여도 **트랙을 알면 계약을 안다.** `contractOf` 가 트랙의 계약을
돌려주도록 고쳤다.

**로그에 없는 것을 "일어나지 않은 일"로 적으면 없는 잘못을 만들어 낸다.**
이 도구가 하지 말아야 할 일이 그것이다.

### 빌드 도구

검사 두 개(색 리터럴 · 명암비)가 `python3` 를 썼다. 파이썬이 없는 자리에서 그 검사가
조용히 건너뛰어지면 검사가 아니라 장식이 된다. 같은 규칙의 Perl 판을 나란히 두고
`py_or_perl` 이 되는 쪽을 고르게 했다. 윈도우의 `python3` 는 스토어 안내문만 찍고
끝나는 껍데기일 수 있어 실제로 돌려 보고 고른다.

보존 구간 `diff` 도 줄끝을 접고 비교하게 했다. CRLF 로 체크아웃한 자리에서는
일곱 구간이 전부 실패해서, 판정이 바뀐 것과 줄끝이 바뀐 것을 구분할 수 없었다.
